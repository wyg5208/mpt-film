# MPT 脚本方案专业模式 + 本地 AI 短剧系列：解决方案文档 + 交互 Demo

## 摘要

用户痛点：视频规划是黑盒——文案→关键词→素材→盲切拼接之间无段落级语义绑定，成片各段互不关联、首尾帧不衔接。**升级目标：让 MPT 具备低成本创作 AI 短剧系列的能力**，充分整合本机已部署的 ComfyUI（含 MiniMax H3 首尾帧视频大模型）、comfy-mini、ACE-Step 音乐大模型、Ollama/llama.cpp 本地大模型，并对 UI 做大胆的小白友好修订。本次迭代交付两件产物（沿用三列重构迭代确立的 doc+demo 模式，**不修改生产代码**）：

1. **解决方案文档** `docs/技术栈阶段总结/2026-11-20_MPT脚本方案专业模式与本地AI短剧系列需求与方案.md`（中文，约 750–950 行）
2. **交互 Demo 扩展**：在 `docs/ui-redesign-demo/` 新增 **创作向导（一句话拍短剧）**、**脚本方案（分镜故事板）**、**系列管理（剧集+角色档案）** 三个菜单页 + 本地引擎模拟，并用无头 Playwright 验证

核心设计决策（文档与 Demo 共同承载）：
- **脚本方案（ScriptPlan）成为一等公民产物**：位于"文案（需求输入端）"与"生成执行"之间，是可见、可编辑、可锁定、可导出的 JSON 分镜脚本；文案页保持纯需求输入定位不变。
- **系列/角色层级（Series → Episode → ScriptPlan → Scene）**：短剧系列需要跨集一致性——角色档案（Character Bible：外貌 prompt + 一次性生成的参考图 + 音色绑定）、场景资产、风格圣经在系列级持久化，每集分镜引用而非重写。
- **本地优先、零边际成本（local-first）**：剧本/分镜 LLM 走 Ollama（MPT 已原生支持）；关键帧图走 ComfyUI t2i + IPAdapter 角色参考；视频走本机 **MiniMax H3 FL2V（首尾帧→视频，含音频 VAE）**；BGM 走 ACE-Step；配音走既有免费 Edge TTS。云端付费源全部保留为可选升级项，每个场景带成本徽标（本地免费 / 云端≈¥x）。
- **首尾帧衔接由模型保证（关键升级）**：相邻场景共享边界帧（场景 N 尾帧 = 场景 N+1 首帧），关键帧由 t2i+IPAdapter 生成后交给 MiniMax H3 FL2V 在首尾帧之间动画化——像素级连续性成为**生成时保证**而非事后审查补救；库存素材源仍用"语义关联标注 + 切点边界审查 + 转场遮蔽"三层策略，不承诺像素连续。
- **草稿/成片双档成本控制**：草稿档用 turbo LoRA 4-step + 768p 快速预览，成片档用完整模型；sha1 requestKey 内容寻址缓存（移植 ChangoVideo comfy.mjs 已验证模式），同 prompt+参数不重复生成。
- **专业模式可选（opt-in）+ 小白向导双轨**：无方案时走现有快速流水线，行为零变化；小白默认落地"创作向导"五步流程（想法→角色→分集→分镜→生成），专业模式直达完整分镜台。术语全部白话化（"首尾帧动画化"而非 FL2V），高级参数渐进披露。
- **时长由旁白驱动**：场景时长 = 该段 TTS 实测时长（sub_maker cues 边界对齐），用户设"目标总时长"，方案生成时按语速估算分配，执行后回填实测值。短剧对白多音色模式列为独立后置批次（独立时间轴装配器，不破坏现有旁白契约）。

### §2 需求完善（逐条回应用户原始描述并纠偏）
- 用户要"视频长度、段落、脚本、字幕、BGM、关联、关键帧"→ 映射为 ScriptPlan 全局字段 + Scene 字段（§4）。
- 纠偏 1：字幕不是 LLM 直接写时间轴，而是 TTS 对齐产物（`task.generate_subtitle` L721，Edge sub_maker / Whisper）；方案中字幕字段是"每场景旁白文本 + 预估 cue 数"，执行后回填真实 SRT 区间。
- 纠偏 2：总时长不可精确预设（TTS 语速浮动），采用"目标时长 ±10% 容差 + 实测回填 + 超差警告"。
- 纠偏 3：首尾帧衔接分源承诺（见摘要）；库存源新增"关联类型"标注（承接/对比/递进/匹配剪辑）让"莫名其妙"变成可解释、可修改的设计决策。
- 补充用户未提但必要的：场景锁定（locked，人工改过的段 AI 不得覆盖，借鉴 OpenFilm locked 轨道语义）、方案版本/修订号、逐场景重生成、方案确认门禁（未确认不允许进入付费生成）、风格一致性约束（style bible：色调/镜头语言/主体描述，注入每个 AI 生成 prompt）。
- **短剧系列目标完善（本轮新增）**："低成本"落地为本地优先引擎栈 + 草稿/成片双档 + requestKey 缓存（§5）；"系列"落地为 Series/Character/Episode 三层模型与跨集参考图复用（§4）；"小白上手"落地为双轨模式 + 五步向导 + 术语白话化 + 就绪度仪表盘（§6）。纠偏 4：角色一致性 v1 不承诺训练级还原（LoRA），采用免训练参考图+IPAdapter 路线并明示能力边界；纠偏 5：多音色对白表演是短剧刚需但破坏现有旁白时间轴契约，列为独立模式后置批次（B6），v1 先交付旁白驱动解说式短剧（与 NarratoAI 路线一致）。

### §3 参考系统分析（互联网检索 + 本机代码核实，借鉴/不借鉴清单）
- **novelvids**（github.com/Anning01/novelvids，开源漫剧/短剧工作台）：借鉴"故事创作→角色资产管理→分镜设计→图片/视频生成"的资产化工作流与本地部署多模型接入；**不借鉴**无限画布（小白门槛高，MPT 用向导+卡片流）。
- **SkyReels**（开源短剧模型）：借鉴"一键剧本→分镜→人物对白→BGM、角色形象/音色可自定义"的产品契约，作为向导五步流程的对标。
- **分镜管理平台实践**（cnblogs Z7TS 2026-01）：借鉴"分镜表格 + 每镜独立选模型（首尾帧→图生视频→配音→合成）"——落地为场景卡引擎选择器。
- **NarratoAI / awesome-ai-short-drama（PAMPAS-Lab）/ DramaCanvas MCP**：借鉴解说式短剧的旁白驱动时间轴（与 MPT 现有 TTS 契约天然吻合）；多智能体编剧→分镜流水线作为 LLM prompt 分阶段设计参考，不引入独立 agent 框架。
- **角色一致性**：StoryDiffusion（consistent self-attention）、IPAdapter 角色参考实践（本机已装 IPAdapter 节点）、Multi-Shot Character Consistency（arXiv 2412.07750）——v1 采用**参考图 + IPAdapter + 固定角色 seed** 的免训练路线；角色 LoRA 训练列为远期可选（成本高、小白不可控）。
- **Wan2.2 FLF2V**（comfy.org 原生支持）：首尾帧→视频范式验证；本机实际权重为 MiniMax H3 FL2V，**以已装模型为准**设计 graph，Wan 权重作为可选下载扩展（WanVideoWrapper 节点已在）。
- ComfyUI：借鉴"每个决策显式可见、可单独重跑"的节点思想，**不借鉴**节点图 UI（学习成本与小白用户群冲突）；MPT 侧只暴露表单化参数（移植 comfy-mini builders 的"模型=成套参数包"理念）。
- ChangoVideo/OpenFilm：借鉴 film-doc.mjs 声明式 clip 时间线（`readFilm` L319、`clipSpan` L398、`clipFade` L441）、FILM_CLOCK 确定性、look/watch 双层校验、comfy.mjs/acestep.mjs provider 契约；**不借鉴**浏览器渲染器（Python 栈不引入 Node+Chromium 运行时，遵循既有融合路线决策 A→C→B 的渐进原则）。

### §5 流水线架构（生产实施设计，本次不写代码）

**5.1 方案生成（本地 LLM 优先）**
- 新阶段 `stop_at="plan"`：`_run_pipeline` 在 script 之后插入；`llm.generate_script_plan()` 复用 `_generate_response` + `_strip_code_fence` + `_extract_embedded_json`，默认 provider=ollama（已原生支持，推荐 gemma4:26b/gpt-oss:20b）；Ollama 路径传 `format:"json"` 约束结构化输出，解析失败→修复重试→**降级为 legacy 扁平脚本**（快速模式不受影响）。分阶段 prompt：故事大纲→角色抽取→分集→分镜（借鉴多智能体编剧流水线，但单 provider 顺序调用，不引 agent 框架）。
- llama.cpp：llama-server OpenAI-compatible 端点，按 Registry 注释 L192–194 新增一条 `llamacpp` 注册项 + 14 locale；或经既有 OneAPI/LiteLLM 网关零代码接入。

**5.2 本地 provider 层（新增三个 Python 服务模块，移植 ChangoVideo 已验证契约）**
- `app/services/comfy_local.py`：裸 origin http://127.0.0.1:8188（config 可覆盖，兼容 comfy-mini 8190 代理）；graph 构建器移植 comfy-mini app.py（t2i L172 起步）+ 新增 **MiniMax H3 FL2V graph**（first/last image 条件 + turbo LoRA 档位 + video/audio VAE）与 **IPAdapter 角色参考 graph**；模型=成套参数包（小白不碰节点）；FNV-1a/sha1 确定性 seed；`/prompt` 提交 + `/history` 轮询 + WS `progress_state`×节点权重折算 0–100%（断线静默降级轮询）；提交后 GET /queue 播报排队深度；sha1 requestKey 内容寻址复用（同 prompt+参数+模型包→直接返回已有产物，跨任务共享缓存目录）。
- `app/services/acestep_local.py`：移植 acestep.mjs 契约（127.0.0.1:8001，300s 预热等待 + 可重试错误文案，**绝不触发 uv sync**）；按 plan.bgm.mood/prompt 生成每集主题曲，复用既有 bgm.validate_audio_file 长轨校验与 bgm_file_override 三态契约（provider 产出绝对路径→跳过 AudioLoop）。
- 健康探测：`GET /system_stats`（ComfyUI）、`/health`（ACE-Step）、`/api/tags`（Ollama）→ 统一 `local_engines_status()` 供 UI 就绪度仪表盘与 preflight 复用；离线时场景引擎选择器自动置灰并提示降级到库存/云端。

**5.3 方案→执行编译器与关键帧链（连续性核心）**
- confirmed plan 编译为逐场景素材请求（keywords/characters/location 绑定场景，替代全局 terms 轮询）+ 显式时间线；`combine_videos` 增加可选 `timeline` 参数（场景→素材 in/out 序列），缺省 None 走原逻辑——最小侵入。
- **本地关键帧链**：① 按 scene.keyframe.first_prompt/last_prompt + 角色 reference_images（IPAdapter）+ style_bible 生成关键帧对（t2i）；② `shared_with_prev` 场景直接复用上一段尾帧文件作首帧；③ MiniMax H3 FL2V 在首尾帧间动画化→场景内部与场景边界像素连续均由模型保证；④ 草稿档 turbo 4-step 768p，成片档完整模型（可接 UltimateSDUpscale）。
- 云端关键帧链（保留升级项）：ffmpeg 抽取已选片段首/尾帧→尾帧作为下一段 seedance/muapi 图生视频首帧条件（seedance payload content 追加 `{"type":"image_url",...}`，L279 处扩展）。
- TTS 对齐：整篇旁白一次 TTS（保留 pause markers/单 sub_maker 契约），cues 时间戳按场景旁白字符边界切窗；多音色对白模式（speaker 字段路由不同 voice_name、逐句 TTS 拼接 + 独立时间轴装配器）列为 B6 独立模式，不破坏旁白驱动主路径。
- 边界审查：`review.py` 新增 `scene_boundary_jump`（切点前后帧差 + 亮度/色度突变，沿用已校准 yuv420p luma 阈值经验），经现有 warnings 通路，零新状态字段；本地 FL2V 场景预期恒 ok，作为回归哨兵。

**6.2 脚本方案页（分镜故事板，专业模式核心）**

  5. **场景详情抽屉**：完整编辑 + 候选素材画廊 + **关键帧对预览/编辑**（上一段尾帧 | 本段首帧 并排 + 差异评分 + first/last prompt 编辑 + [本地生成首帧][本地生成尾帧]）+ requestKey 缓存命中提示（"此画面已生成过，直接复用"）。
