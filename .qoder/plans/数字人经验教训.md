## 二、证实的产品缺口（按价值排序）

**P0 —— 直接消除本次复盘中的返工**

1. **ACE-Step 不在 GPU lease 内**。[acestep.mjs](file:///d:/python_projects/moneyprintturbo/opensources/changovideo/packages/changovideo/studio/server/providers/acestep.mjs#L64-L70) 的 `run()` 直接提交任务，没有 `withGpuLease`；gpu.mjs 注释也只写了 face2face + ComfyUI。复盘里"ComfyUI→DUIX→ACE-Step 手工排队"正是这个缺口的代偿——并行时有真实 OOM 风险。修法很小：把 `music()` 包进 lease。

2. **DUIX 回执时长量错了对象**。[duix.mjs L97-99](file:///d:/python_projects/moneyprintturbo/opensources/changovideo/packages/changovideo/studio/server/providers/duix.mjs#L97-L99) probe 的是**配音音频**（29.304s），`collect()` 却把它当**成片时长**写进 receipt/index，注释还声称"measured here"。实际容器 29.288s，于是 `#t=0,29.304` 被拒——复盘坑 #4 的根因就在这。应改为 probe 渲染回来的 clip 本身。

3. **DUIX 等待预算低估冷启动**。[timing](file:///d:/python_projects/moneyprintturbo/opensources/changovideo/packages/changovideo/studio/server/providers/duix.mjs#L34) `minBudgetSec=180`、`REALTIME_FACTOR=4`，29s 口播预算只有 180s，而复盘实测首跑（含模型预热）常超。幂等重跑虽兜底，但每次冷启动都多一轮人工往返。更优解：进度仍在推进就顺延 deadline（停滞才超时），比单纯调大常数更稳。

**P1 —— 消除高危手工操作**

4. **没有 CLI 侧的停止命令**。`/api/quit` 其实认 `x-studio-key`（[server.mjs authorize](file:///d:/python_projects/moneyprintturbo/opensources/changovideo/packages/changovideo/studio/server/server.mjs#L348-L353)），复盘里 401 是因为裸 HTTP 没带 key；[client.mjs 的 replace()](file:///d:/python_projects/moneyprintturbo/opensources/changovideo/packages/changovideo/studio/client.mjs#L130-L144) 内部已有完整的"带 key 退出 + 杀 supervisor"逻辑，只是没暴露成 `changovideo quit/stop` 动词。补上后，"taskkill + 手删带 key 的临时 home"这套危险收尾就不需要了。

5. **keyless 本地 provider 只能在 Studio UI 连接**。CLI 只会说 "Not connected here…去 Settings 连"（[get.mjs](file:///d:/python_projects/moneyprintturbo/opensources/changovideo/packages/changovideo/studio/server/get.mjs#L141-L151)），agent 被迫手改 `providers.json`。"本人同意后才服务"是有意设计（有测试守住），但可以增加一个本人授权的 `changovideo connect <id>`（仅限 keyless），保留同意门禁、去掉手改 JSON 的风险。

6. **env 绑定型 provider 与复用 Studio 的冲突无提示**。`CHANGOVIDEO_DUIX_TEMP` 只读 Studio 进程 env，CLI 复用桌面 Studio 时必然缺失，而报错文案没提示"你复用的是另一个进程"。两个方向：把 DUIX temp 目录做成 provider 设置项（随 providers.json 走，运行时读取），或至少在 `get` 检测 env 缺失时指明复用冲突。前者能根除"隔离 home + 杀进程 + 删 key 副本"整条 workaround。

**P2 —— 校验与装配体验**

7. **`look` 对字幕层零感知**。[look.mjs](file:///d:/python_projects/moneyprintturbo/opensources/changovideo/packages/changovideo/src/look.mjs) 全文没有 subtitle/vtt 相关逻辑，复盘坑"帧里没字幕别误判"只能靠人记住。低成本改法：look 输出字幕状态行（on/off、vtt 配对、cue 数、位置），缺配对时给 warning；画进帧里是更大的工程，可后置。

8. **时长有三个真相源**：回执估算（`mp3Seconds` 2.066）、ffprobe（2.0376）、引擎校验用的浏览器 metadata（2.0）。whoosh 那个坑的根因是 agent 拿不到引擎口径的时长。`__filmSpans` 已暴露 `native`，让 `look` 联络表顺带打印每个素材的引擎口径时长，装配时就不用"整数秒减 0.05"这种猜测式经验。

9. **vtt 词级时间 → film_t 换算纯手工**。复盘称之为"最重要的一条公式"，每次都要重推。一个小工具（输入 vtt + 偏移 + speed，输出贴片时间表）即可产品化；逐素材 LUFS 同理可并进 look 输出。

## 三、结论

复盘质量很高，但它把三类东西混在了一起：**已内建的能力**（幂等、部分 GPU 串行）、**真实产品缺口**（上面 1–6）、**纯工艺经验**（布局坐标、电平配比）。值得立项完善的是 P0 三项 + P1 的 quit 动词——都是小改动，且每项都能直接删掉复盘里的一条"坑与对策"。P2 属于体验增益，可以随下个迭代顺带做。
