# 一、并行出帧与确定性校验的实现机制

## 1.1 职责切分：浏览器只画一帧，ffmpeg 负责其余一切

[render.mjs](file:///d:/python_projects/moneyprintturbo/opensources/openfilm/packages/openfilm/src/render.mjs) 的核心是 `encode()`（第 435–491 行），它是一台"帧泵"：

```
film.seek(t)  →  film.capture(png|jpeg)  →  写进 ffmpeg 的 image2pipe stdin
```

`format=f'{image2pipe} -framerate fps*samples -c:v mjpeg|png'`，编码器只做压缩，完全不知道页面是什么。**并行 = 帧区间切片**：

```js
const per = Math.ceil(total / workers);
parts = pages.map((film, i) => ({film, a: f0+i*per, b: min(f1, f0+(i+1)*per), file: `part-${i}.mp4`}));
```

各 part 独立编码 → 最后 `concat` demuxer + `-c copy` 拼接（第 316–321 行）。不二次编码，零代际损失。若只有 1 个 part 且无音轨无后置参数，直接 `rename` 到位（`moved()`），磁盘峰值只有一次。

## 1.2 三个容易被忽略但决定正确性的细节

**① 预热丢弃两帧**（第 454–460 行）。注释说得很直白：一个 tab 的头两张图会略微偏离后续帧（透明页面的软边差 1–2 个色阶）。所以每个 worker 先画 `a-2`、`a-1`（钳到 `first`）并丢弃，再从 `a` 开始输出。效果：**同一帧的像素与"这次用了几个浏览器"无关**。这是并行渲染能被复现的前提条件，绝大多数自研管线会漏掉。

**② 子帧采样 → tmix 平均，而不是在页面里做模糊**（第 436、470–473 行）。`samples>1` 时一帧内多次 seek：

```js
t = (frame + (k/samples - 0.5) * shutter) / fps   // shutter 默认 0.5
```

每帧喂 `samples` 张图给 ffmpeg，滤镜链是 `tmix=frames=N, select='eq(mod(n,N),N-1)', setpts=...`。所以运动模糊是**解码侧的平均**，页面只要满足"帧只依赖 t"就能被任意时刻采样——这正是 SPEC §3 授权 host "at fractional frame times" 的用意。

**③ 每 worker 独立编码器 → 内存是瓶颈**（第 64–77 行）。`outOfMemory()` 识别 x264 的 `malloc of size N failed`、ENOMEM、Windows `STATUS_NO_MEMORY (3221225495)`，给出的建议是**减少浏览器数**（`--workers n/2`），因为"每个浏览器各自喂一个编码器"。

## 1.3 机器预算：`machine()` + `defaultWorkers()`（第 363–403 行）

```
workers = clamp(1 .. min(4, cores-1, floor((free - 2GiB)/1.5GiB), floor(frames/60)))
```

四条经验值都带测量注释：每浏览器 1.5 GB（1080p 实测 1.1 GB + 编码份额）、给人留 2 GB、每 60 帧才值得多开一个、**超过 4 个反而更慢（共享同一块 GPU：3 个是 1 个的两倍速，8 个耗尽资源）**。macOS 特例：`os.freemem()` 只统计"从未用过的内存"，所以改读 `kern.memorystatus_level`，并且核数取 `hw.perflevel0.physicalcpu`（性能核，效率核画 WebGL 太慢）。`cores-1` 的语义是"渲染期间电脑还能正常用"。

## 1.4 浏览器生命周期与故障分类

[browser-pool.mjs](file:///d:/python_projects/moneyprintturbo/opensources/openfilm/packages/openfilm/src/browser-pool.mjs)：Studio 导出逐页复用浏览器（`take/give`），一个浏览器画满 `PAGES_PER_BROWSER=24` 页就换新（实测内存 20 页内是平的，这条只是兜底），崩溃的、渲染没能善终的（`retire`）都直接关掉。

`browserFailed(e)`（第 82 行）用一条正则把失败分成两类，这是很值得抄的**错误分类学**：

| 分类 | 判据 | 处置 |
|---|---|---|
| 浏览器死了 / 卡住 | `target crashed`、`browser disconnected`、`did not finish within`、`net::ERR_NO_BUFFER_SPACE`、`video is shown another way from now on` | 换新浏览器**重画** |
| 页面自己的错 | `frame(t)` 抛异常、文件缺失、代码死循环 | 重试必然再失败，直接报给用户 |

`render()` 里还有两个 Windows 细节：`finally` 中 `rmSync(..., maxRetries: 5)` 并 `catch {}`（ffmpeg 退出后文件句柄晚一点才放，宁可留残留也不要顶替真正的错误）；`kill()` 用 `taskkill /T /F` 杀整棵树（很多 Windows 上的 ffmpeg 是 shim，真进程是子进程，不杀干净会一直占着管道）。

## 1.5 视频素材的"帧精确 seek"是被工程手段解决的，不是被约定的

这条最容易低估，[host.mjs](file:///d:/python_projects/moneyprintturbo/opensources/openfilm/packages/openfilm/src/host.mjs) 与 `seekable.mjs` 花了很多力气：

- `SEEK_INSIDE_FRAME`（第 15 行）重写 `HTMLMediaElement.currentTime` 的 setter，把 `t` 变成 `t + 0.001`。注释：否则**约 1/3 的概率显示上一帧**。
- `frameDuration(file)`（第 173 行）用 ffprobe 拿帧长，通过 `/__film/frame-duration` 端点暴露给 timeline，实现"seek 落在帧内"而不是"落在时间上"。
- `presentsVideo(browser)`（第 308 行）：内置两段 2 秒测试片（H.264 + HEVC Main10 的 base64），逐个 seek 并用 `requestVideoFrameCallback` + `meta.mediaTime` 校验"显示的就是 seek 到的"。因为某些 Windows + Vulkan 组合下**永远收不到帧**，每帧白等 5 秒或直接黑屏。
- `vulkanFirst()`（第 364–431 行）是一台探测状态机：Vulkan → 检查 GPU 与是否真能显示视频 → 不行则 D3D11 同 GPU → 不行则 Vulkan + `--disable-accelerated-video-decode`（笔记本双显卡时保住独显跑 WebGL）→ 不行则 D3D11 另一张卡 → 都不行用默认。选定结果缓存给后续所有浏览器。运行时若发现"整片视频帧一次都没出现"（`__filmVideos()` 返回 `shown===0 && unshown>=3`），抛 `VideoNotShown` 并**换一种方式重画整片**。
- 浏览器解码不了的素材（ProRes / 无芯片的 HEVC）以及"长素材慢 seek"，用 `browserCopies()` 预生成一份浏览器能放的副本，靠 HTTP 层的 `swap(file)` 在**服务时偷梁换柱**，页面与 film.html 都不用改。失败则记入 `uncopied` 并在 lines 里明说"按原样绘制"。

## 1.6 `look`：把确定性从"约定"变成"保证 + 校验"

两层。

**第一层是保证**：`FILM_CLOCK`（host.mjs 第 24 行，一段压缩注入脚本）在 `filmHost.time(t)` 之后把页面能读到的所有时间源锁死在 `t`：

| 页面可读到的 | 被改成 |
|---|---|
| `performance.now()` | `t*1000` |
| `requestAnimationFrame` 回调的时间戳 | `t*1000` |
| `Date.now()` / `new Date()` | `2026-01-01T00:00:00Z + t` |
| CSS Animations / Web Animations | `pause()` + `currentTime = t*1000`；`CSSTransition` 直接 `finish()`（它的进度是历史，不属于 t） |
| `Math.random()` | 种子 = `round(t*1e6) ^ 0x2545f491` 重播；加载阶段用固定种子 |
| 首帧之前（`ready`、加载） | 走真实时间——否则等字体/等模型的代码会挂 |

`filmHost.now()` 保留真时钟给 host 自己等东西用。[host-clock.test.mjs](file:///d:/python_projects/moneyprintturbo/opensources/openfilm/packages/openfilm/src/host-clock.test.mjs) 就是这条的验收测试，断言细到"一个 CSS keyframes 动画在 `time(2.5)` 后 `width` 必须是 `250px`"。**结果：即使页面作者违规（rAF 循环、CSS keyframes、粒子随机），画出来仍然对。**

**第二层是校验**（[look.mjs](file:///d:/python_projects/moneyprintturbo/opensources/openfilm/packages/openfilm/src/look.mjs)）：

```js
const first  = await pass(shuffled(times, 1), true);   // 顺序 A + 顺手扫文字
const second = await pass(shuffled(times, 2));         // 顺序 B
if (compare(times.map(t => [t, first.get(t), second.get(t)]))) passed.push('...same t, same picture');
```

- 采样时刻由 [samples.mjs](file:///d:/python_projects/moneyprintturbo/opensources/openfilm/packages/openfilm/src/samples.mjs) 的 `sheetTimes(from,to,n)` 给出：**除以 `n-1`，首尾都取**。注释解释得很清楚——除以 `n` 会漏掉片的最后一格，而"画两遍比对"就看不见"只在结尾变"的页面。这个一行函数我认为是全仓库最浓缩的正确性设计。
- 顺序用固定哈希打乱（`shuffled(list, seed)`，shared.mjs 第 439 行），**每次运行同一顺序，但不是页面自然顺序**。
- 比对不逐字节：先 sha1，不同再用 `blockDiff()`（shared.mjs 第 359–374 行）——把两图各降采样到 `W/8 × H/8`，取 4 通道最大绝对差，`SAME_LIMIT = 32` 以上才算真不同。抗锯齿噪声（文字边缘重栅格化差 1–2 级）平均后在 20 以下。
- 判失败的输出直接把病因写进文案（look.mjs 第 209–212 行）：时钟、未播种随机、跨调用状态、GSAP `to/from` 从屏上取起始值（改用 `fromTo`）、媒体还在 seek；并落 `-a/-b` 两张 PNG 让你对比。
- 单帧模式 `look 7.5` 用另一手法：画 `t`，再画半片远处的一帧，再回 `t` 画一遍——**中间插入别的帧**才叫检验顺序无关性。

**结构性检查**（一次调用全跑，全部输出成"行"）：

| 检查 | 手法 | 级别 |
|---|---|---|
| 契约校验 | `duration/width/height` 类型、声音文件是否存在、页面还写 `window.film.audio`（不会被播）、`film.html` 解析问题一次性全列（`readFilmFile().problems`，早于开浏览器） | ✗ |
| 同轨重叠 | `__filmSpans()` 排序后 `clip.at < before.end - 0.001` | ! |
| 画面什么都没画 | `__filmCuts()` 每个片段**中点**取帧，`spread()` < 6（8×8 平均后 luma 极差）= 一片纯色 | ! |
| 文字被裁 | `cutText()` 在**每个 frame 上下文**里 TreeWalker 遍历文本节点 + `Range.getBoundingClientRect()`，判 `edge`（超出舞台 ±2px）与 `box`（祖先 `overflow:hidden|clip` 裁掉），**≥2 帧才警告**（单帧可能是入场中） | ! |
| 字体加载失败 | `document.fonts` 里 `status==='error'` 的 family | ✗ |
| 软件渲染 | WebGL renderer 命中 `swiftshader\|llvmpipe\|software\|basic render` | ! |
| 声音 | 每个音频 `astats` 读 Peak，≤ −30 dB 提示"混音里听不见"；整片 `ebur128` 报 LUFS/true peak 与到目标的距离 | ! / ♪ |
| 全同帧 | 所有采样帧 sha1 相同 → "frame(t) 可能没画任何随 t 变化的东西" | ! |

输出契约就一句话：`{ok, lines, files}`，`ok = errors.length === 0`，`lines` 前缀是 `film … / ♪ / ✗ / ! / ✓ / →`。**没有 JSON schema，文本就是接口**，对 LLM 极友好。

## 1.7 `look --full`：逐帧缺陷检测（`watch.mjs`）

这是"渲完之后看整片"的回路，实现非常省：

```
[0:v]fps=10,scale=96:54,format=gray[A];
[0:v]scale=64:36,format=gray,pad=96:54[B];
[A][B]vstack  →  -f rawvideo pipe:1
```

**一次解码，两路尺寸，一条 stdout**（每帧 `96×(54+36)` 字节，Python/Node 侧按固定长度切流）。10 fps 那路查慢缺陷，原帧率那路查只存在 1–2 帧的闪白（10 fps 会跨过去）。

阈值表 `WATCH`（8-bit luma）：

| kind | 判据 |
|---|---|
| `flash` 白闪 | 相邻帧均亮差 > `flashUp=18` 且 `flashBack=12` 秒内回落；或一帧比两侧都亮很多（`jump>14` 且两侧互相接近 < `max(5, 0.35×min)`） |
| `jump` 跳帧 | 同上但亮度不突出 |
| `still` 静帧 | 逐帧均差 < `still=0.35` 且与段首差 < `drift=0.5`，持续 `stillFor=6` 秒 |
| `dark` 黑屏 | ≥ `0.995` 像素 < `dark=24`，且首/尾短于 `fade=0.5s` 的段豁免（那是淡入淡出） |

去重规则也写死了：同一缺陷在两路速率都命中只说一次；被判 `flash` 的帧不再判 `jump`；相邻 ≤0.1 s 的同类区间合并。`still` 的文案特意加"如果是片尾卡帧就是正常的，人来判断"——**只报事实，不冒充决策**。`lookRendered` 还会比对 `film.html` 与 mp4 的 mtime，若源文件在渲染后又改了，插一行"这是片子当时的样子"。

## 2.6 明确不建议照搬

# 三、`SPEC.md` vs `docs/video-projects.md` 的工程格式设计对比

两份文档我都读完了（`SPEC.md` 217 行 / Protocol 0.1；`video-projects.md` 161 行 / `SCHEMA_VERSION = 1`）。它们解决的是**同一个问题的两极**。

## 3.1 总览

| 维度 | OpenFilm SPEC | MPT video-projects |
|---|---|---|
| 事实源 | `film.html` 本身（HTML + CSS），可直接被浏览器当网页打开播放 | `episode.json` manifest（纯 JSON），不可独立播放，必须 renderer |
| 单元 | clip = 一个 DOM 元素 | scene = 一个 dict `{id, footage, audio, narration, duration}` |
| 时间定位 | 媒体片段 `#t=in,out`（文件自身秒） | **无 in/out**：整文件循环或截断（doc 第 73–75 行） |
| 空间定位 | `style` 的 `left/top/width/height` + `rotate`，外观是 CSS | **无**：只有全局 `settings.width/height/fps` |
| 声音 | 每个声音都是片段（`<audio>` 或视频自带声），可放置/裁切/静音/改量 | 场景旁白（必填文件）+ 一个全局 `bgm` + 两个 volume |
| 字幕 | "Words" 约定：音频旁同名 `.vtt`，cue 即一行、tag 到词，`1.<lang>.vtt` 是译文；编辑器据此生成，**绝不在页面里画字幕** | **明确未实现**（第 82–84 行：word-aligned subtitles、transitions、overlays、provider generation 都不做） |
| 帧率 | 不是片子的属性，是渲染时决定的（SPEC §2 第 145 行）；时间是"到毫秒的秒"，每个数各自四舍五入 | `fps` 在 `settings` 里，进指纹：改 fps → 重建 scenes + assembly + export |
| 人改 vs 机改 | `overrides`（元素级：`at` 选择器 / `text` / `t` / `s` / `r` / `style` / `lock` / `fade`）内联在同一文件里，智能体编辑时**必须保留**；轨道级 `locked`/`hidden`/`muted` | **不合并**：改动 = 新 revision（`revise`）；保留 `scene.id` 才能对比（`compare OLD NEW`） |
| 确定性 | §3 规范条款：同 `t` 必同图，host 靠它乱序/并行/子帧渲染 | 无画面确定性；只有**字节可复现**：SHA-256 快照 + `RENDERER_VERSION` + ffmpeg/ffprobe 版本 + settings 指纹 |
| 增量 | "one shot per page" → 重渲一个镜头 = 重画一个页面 | `plan` 列出要重建的 stage，6 行"改动 → 重建阶段"对照表（第 97–105 行） |
| 素材可变性 | 引用不可变：`#t=` + CSS 裁，**永不裁切/重编码成新文件** | 字节不可变：源文件**复制进工程**做快照（第 66–68 行"改原文件不会悄悄改 revision"） |
| 扩展策略 | §1 末给出**加属性的判据**（改变片子或是人机约定、且无法用 CSS/页面/文件表达），§5 单调演进："新属性可加，缺失必须保持今天的含义" | `SCHEMA_VERSION=1` + 未知字段**直接拒绝**（第 137 行，连 provider credentials 一起挡） |
| 错误模型 | 严格解析：拼错的属性、多余元素**连行号报出**，不忽略（`film-doc.mjs`）；`open()` 打开浏览器前就把 `problems` 全列出来 | `ProjectError` + `_ID` 正则 + 1..100 scenes 上限；原子替换、OS 锁、`cancel` 文件、`--stage-timeout`（默认 600 s）、`.work` 目录永不可信 |
| 攻击面 | 浏览器会执行代码：目录限定 HTTP 服务、`../`+`%2F`+`\`+NUL 校验、`realpath` 符号链接逃逸、`readableLink` 白名单、`?film-host=0` 可取原始页、`offline` 模式 route 拦外部 origin | ffmpeg 参数注入：禁网络协议、拒 HLS/DASH/concat 播放列表与外链素材、manifest 不放凭据、`list.txt` 用文件名不用路径 |
| 编辑器状态 | 不进 `film.html`，放 `.film/`；输出进 `.film/cache/{look,render}` | `project.json` 指向当前 revision 与最后一次成功 export（新版本成功前不替换） |
| 复用单位 | skill（10 个类型片手册）+ 页面共享的文件（字体/色板/logo） | preset（`save-preset`：尺寸、fps、旁白/BGM 音量），**明确不含素材、工程 ID、凭据、provider 选择** |
| 互操作对象 | 第三方 host/播放器/渲染器/编辑器（协议 + `filmHost.version` 协商），导出 FCPXML/Premiere/DaVinci/剪映 | 内部"future accepted director"（第 155–158 行的 `VideoProject.create_revision/plan/render/status/compare` API 边界） |

## 3.2 三个真正值得学的点

**① 两份文档都花力气约束"格式自己不要长大"，但用的杠杆不同。**
`SPEC.md` §1 最后一段是全仓库最有分量的一段设计自律：属性只在"它改变片子、或是人机之间的约定、且无法用 CSS/一个页面/一个文件表达"时才加，并举了反例——"一个转场效果是页面，一次调色是一个文件"。`video-projects.md` 用另一种方式达到同样克制：preset 里"不含素材、不含凭据、不声称 AI 角色一致性"，manifest 未知字段一律拒绝。前者靠**语义准入**，后者靠**结构封闭**。对一个正在被大量 provider 请求冲刷的项目（MPT 的 `services/` 已经有 30 多个 provider 文件），`SPEC.md` 那条准入判据比 schema 校验更有用——它能挡住"每加一个供应商就加 3 个字段"的退化。

**② 确定性有两种，别混用。**
`SPEC.md` 要的是**语义确定性**（same `t` → same picture），服务于乱序并行与子帧采样；MPT 要的是**出处确定性**（same bytes → same artifact），服务于不重跑与可审计。二者互补而非竞争：`video_projects.py` 的 `_fingerprint` + 内容寻址产物已经是后者的完整实现（第 176/228/230 行）。MPT 缺的正是前者（P-1），而拿到前者的成本只是 5 处 `random` 换成 `rng`。**这是本轮分析里我认为最应马上动手的一件事。**

**③ "时间"的表示法决定了格式的表达能力。**
`SPEC.md` 把时间定为"到毫秒的秒，每个数各自舍入"，并推出精确后果："同轨重叠 ≤1ms 视为相接"（§1 第 87–89 行）。这一句就消灭了 `checkOverlaps` 的浮点假阳性。MPT 的 manifest 没有 in/out、没有位置、没有 fps 之外的时间语义，所以它的"改动 → 重建"表只能到"场景/装配/导出"三级；一旦要表达"这段素材取 12.2–15 秒"，就必须引入片段标记这一层。也就是说 **MPT 的 manifest 目前是"素材清单 + 渲染参数"，`film.html` 是"时间线本身"**。命名要诚实：`episode.json` 不该被宣传成可编辑时间线。

## 3.3 若要给 MPT 的工程格式做 v2，我建议吸收这 4 条

1. **`scenes[].in` / `scenes[].out` / `scenes[].speed`**（对应 `#t=in,out` + `speed`）：现在"短素材循环、长素材截断"无法表达取用哪一段。规则沿用 SPEC 的"永不把素材裁成新文件，裁切发生在渲染时"，与 MPT 现有 `SubClippedVideoClip(start_time,end_time)` 天然对齐——**只是 manifest 还没把它暴露出来**。
2. **`scenes[].title` / `narration` 旁边挂 WebVTT 约定**：`footage.mp4` → `footage.vtt`，cue 即一行字幕、词级 tag，译文 `footage.<lang>.vtt`。MPT 已经有全部原料（`voice.py` 的 `_build_subtitle_items_from_edge_cues_words`、`utils/subtitle_reader.py`、`subtitle_writer.py`、`subtitle_shaping.py`），差的只是**约定文件名**而非字段名。这一步同时能填上 doc 第 82–84 行列的"未实现"。
3. **时间统一到毫秒 + "≤1ms 重叠视为相接"**，把 `_VIDEO_DURATION_SAFETY_MARGIN = 0.1` 这类经验常量换成显式的时间舍入契约 + review 检测。
4. **`scenes[].locked`（人改过，渲染器与智能体都不得动）**：这是 `locked` 轨道语义在 JSON 里的最小移植，不需要 `overrides` 的元素级复杂度。同时把 `SCHEMA_VERSION` 加上"未知字段是拒绝还是警告"的显式策略位（现在是硬拒绝，对内部 API 合适，对"future director"传新字段会直接崩）。

反向也有一条给 OpenFilm 的：`video-projects.md` 的**并发与善后纪律**比 SPEC 强得多——单渲染器写同一 revision、不同 revision 可并行共享只读产物、崩溃后状态可能停在 `running` 必须 `--retry` 重验、`.work` 永不可信、每个外部命令有 deadline。SPEC 只字未提并发与中断恢复（它是格式规范，不该承担），但 MPT 在把这套接进 `task.py` / `state.py` 时，这些正好是 review 闭环之后最容易被忽略的坑。

## 本轮结论与下一步

分析结论：OpenFilm 的确定性不是靠"要求作者写纯函数"，而是靠**把页面的时钟、动画和随机数劫持到 `t` 上**（`FILM_CLOCK`）+ **用两种打乱顺序重绘来验证劫持是否成功**（`blockDiff`/`SAME_LIMIT`）+ **渲完之后逐帧复检**（`watch.mjs` 双速率单流）。MPT 能拿走的是后两层以及那个"文本即接口"的输出格式，第一层（劫持时钟）在 MoviePy 世界里对应的是消灭全局 `random`。

建议按 P0（seed）→ P1（`review.py`）→ P2（接入 warnings/CLI/SKILL）顺序落，P0+P1 两天内能出可见收益，P3 的响度目标视平台需求决定。
