## 1. 现状审计（全部锚点已于 2026-11-20 复核）

用户痛点：**视频规划是黑盒**——文案→关键词→素材→盲切拼接之间没有段落级语义绑定，
成片各段互不关联、首尾帧不衔接，"经常莫名其妙"。逐环节审计如下：

| 黑盒环节 | 锚点 | 问题 |
| --- | --- | --- |
| 脚本生成 | `app/services/llm.py` `generate_script` L911–1007、`build_script_prompt` L875 | 只产出纯文本旁白，无结构化场景；段落边界只存在于换行符里 |
| 关键词 | `llm.py` `generate_terms` L1040–1100 | 扁平列表；`match_script_order` 仅保证素材顺序与脚本大致同序，无"哪段文案配哪段画面"的绑定 |
| 流水线 | `app/services/task.py` `_run_pipeline` L1971–2416 | script→terms→audio→subtitle→materials→rendering 六阶段，**没有 plan 阶段**，用户看不到也改不了中间决策 |
| 编排 | `app/services/video.py` `combine_videos` L987–1320 | 把素材盲切成 ≤5s 子片段，随机/轮询凑满音频总时长；转场按片段 RNG 随机——这是"各段互不关联"的直接根因 |
| AI 视频源 | `app/services/volcengine_seedance.py` L277–283 | payload content 仅 text，无 `image_url` 首/尾帧条件化；全仓库 grep `first_frame`/`last_frame` 零命中——首尾帧衔接能力缺失 |
| 审查 | `app/services/review.py` + `task.py` L1256–1268 | 仅成片事后审查（闪帧/跳变/静帧/暗场），无"切点边界"专项检查，警告无法定位到场景 |
| 可复用底座 | `app/services/video_project.py`（scene spec、`stage_graph` L171–243 指纹增量、`_atomic_json` L61 / `_lock` L75 原子写与 OS 锁）、`determinism.py`、`llm.py` `_strip_code_fence` L1010 / `_extract_embedded_json` L1026、`docs/video-projects.md` L153–160 "future accepted director" 边界 | 结构化场景、确定性种子、JSON 解析、增量渲染、原子持久化的轮子都已存在，**不重造** |
| 本地 LLM 已就绪 | `app/models/llm_provider.py` L591–596 原生 `ollama` provider（`requires_api_key=False`，免 Key）、`llm.py` L360–363（ollama 默认 base_url 解析）、`app/config/config.py` L430 `get_default_ollama_base_url`（含 Docker 网关处理）；Registry 注释 L192–194：新增 OpenAI-compatible provider 只需一条注册项 + locale | **Ollama 零开发成本**；llama.cpp 走 llama-server OpenAI-compatible 端点同法接入 |

**结论**：问题不在渲染质量，而在"决策不可见、不可改、不可锁定"。修复方向是在文案（需求输入端）
与生成执行之间插入一个**一等公民产物——脚本方案（ScriptPlan）**，把黑盒里的每个决策显式化；
短剧系列目标则在其上再加一层 **Series/Episode/Character 资产层**（§4），跨集复用一致性约束。

## 2. 需求完善（逐条回应用户原始描述并纠偏）

用户要"在视频设计环节就非常细致地输出视频长度、段落、脚本、字幕、背景音乐、视频之间的关联、
关键帧或图片"→ 全部映射为 ScriptPlan 全局字段 + Scene 字段（§4），在生成**之前**可见可编辑。

### 2.1 五处纠偏（用户直觉与系统物理的冲突）

1. **字幕不是 LLM 直接写时间轴**。字幕是 TTS 对齐产物（`task.generate_subtitle` L721，
   Edge sub_maker / Whisper）。方案中的字幕字段是"每场景旁白文本 + 预估 cue 数"，
   执行后回填真实 SRT 区间——LLM 写时间轴必然与语音漂移。
2. **总时长不可精确预设**。TTS 语速浮动，场景时长 = 该段旁白实测语音时长。采用
   "目标总时长 ±10% 容差 + 按语速估算分配（中文 ≈4.2 字/秒）+ 执行后实测回填 + 超差警告"，
   而不是让用户自由指定每段长度再强行拉伸画面。
3. **首尾帧衔接必须分源承诺**。本地 AI 源（MiniMax H3 FL2V）与云端图生视频源可以做像素级
   衔接：上一段尾帧作为下一段的首帧条件（关键帧链，§5.3）；**库存素材物理上做不到像素连续**，
   改用三层策略：语义关联标注（承接/对比/递进/匹配剪辑，让"莫名其妙"变成可解释、可修改的
   设计决策）+ 切点边界审查（`scene_boundary_jump` finding）+ 转场遮蔽（fade/slide/zoom 吸收突变）。
4. **角色一致性 v1 不承诺训练级还原**。角色 LoRA 训练成本高、小白不可控；v1 采用
   **免训练参考图 + IPAdapter + 固定角色 seed** 路线并在 UI 明示能力边界（"同一套参考图注入
   每集关键帧，长相跨集一致"），LoRA 仅作预留挂载点（`lora: null`）。
5. **多音色对白表演是短剧刚需，但破坏现有旁白时间轴契约**。逐句多音色 TTS 拼接需要独立
   时间轴装配器，列为独立后置批次（B6）；v1 先交付**旁白驱动解说式短剧**（与 NarratoAI
   路线一致，天然吻合 MPT 现有单 sub_maker 契约），`speaker` 字段先行预留。

### 2.2 用户未提但必要的补充

- **场景锁定（locked）**：人工改过的段，AI 重生成不得覆盖（借鉴 OpenFilm locked 轨道语义）。
- **方案版本/修订号**：`plan_version`（schema 版本）+ `revision`（每次人工/AI 修改递增），可追溯。
- **逐场景重生成**：不满意只重掷一段，保留场景 id 与其余段不动。
- **方案确认门禁**：未确认的方案不允许进入付费生成；确认即冻结修订号。
- **风格一致性约束（style bible）**：色调/色彩/镜头语言/时代世界观，注入每个 AI 生成 prompt。
- **引擎离线降级**：本地引擎离线时选项置灰 + 白话提示，可一键降级为库存素材；快速模式不受影响。
- **requestKey 缓存复用**：同 prompt+参数+模型包的画面请求命中缓存直接复用，不重复烧显卡
  （ChangoVideo `comfy.mjs` sha1 requestKey 路线已验证）。
- **草稿/成片双档**：草稿档 turbo LoRA 4-step + 768p 快速预览（几分钟），成片档完整模型
  （可接 UltimateSDUpscale）；先看效果不心疼，确认后一键升级。

### 2.3 短剧系列目标完善（本轮新增）

- **"低成本"** 落地为本地优先引擎栈（§1b）+ 草稿/成片双档 + requestKey 缓存（§5）。
- **"系列"** 落地为 Series → Episode → ScriptPlan → Scene 层级模型与跨集参考图复用（§4）：
  角色档案（Character Bible：外貌 prompt + 一次性生成的参考图 + 音色绑定 + 固定 seed）、
  场景资产（locations）、风格圣经在系列级持久化，每集分镜**引用而非重写**；
  修改影响后续生成，已渲染集不受影响。
- **"小白上手"** 落地为双轨模式 + 五步向导 + 术语白话化（"首尾帧动画化"而非 FL2V）+
  本地引擎就绪度仪表盘 + 高级参数渐进披露（§6）。
- **分集大纲 + 集尾悬念**：短剧留存的关键是每集结尾的钩子；大纲阶段显式建模 `hook` 字段。

## 4. 核心数据模型（完整 JSON Schema + 字段表，三层：Series / ScriptPlan / Scene）

ScriptPlan 是单一事实源；Demo `app.js` Block A（`mkScene`/`seedShortDrama`）已按下述 schema
实现参考版本（字段别名见附录 A），生产模型落 `app/models/schema.py`（B2）。

### 4.1 系列层 Series（新增，短剧系列跨集一致性的根）

```json
{
  "series_version": 1, "id": "sr-xxx", "title": "...",
  "genre_template": "urban_revenge|period_romance|suspense|healing|scifi|custom",
  "style_bible": { "tone": "...", "palette": "...", "camera": "...", "era": "..." },
  "characters": [{
    "id": "c1", "name": "...", "role": "protagonist|support|extra",
    "appearance_prompt": "外貌/服装描述（注入每次关键帧生成）",
    "reference_images": ["characters/c1/ref-1.png"], "seed": 900001,
    "voice_name": "zh-CN-YunxiNeural", "personality": "...",
    "lora": null
  }],
  "locations": [{ "id": "l1", "name": "...", "prompt": "...", "reference_images": [] }],
  "episodes": [{
    "id": "ep1", "seq": 1, "title": "...", "logline": "...",
    "hook": "集尾悬念", "plan_id": "...",
    "status": "draft|confirmed|rendered"
  }]
}
```

设计要点：

- **Character Bible 三件套**：`appearance_prompt` + `reference_images` + `seed` 共同构成角色
  一致性约束——每次关键帧生成注入同一套参考（IPAdapter）与固定种子；`voice_name` 绑定音色
  供 B6 多音色对白模式路由；`lora` 预留挂载点（默认 null，不强制训练）。
- **参考图一次生成、跨集复用**：内容寻址命名存 `characters/{cid}/`，重生成形象=换 seed 重掷
  参考图组，旧图保留可回退；人工锁定后 AI 不得覆盖。
- **风格圣经系列级持久化**：每集 plan 的 `style` 字段是引用快照；系列修改后新集生效，
  已渲染集不受影响。
- **剧集状态机**：`draft → confirmed → rendered`（大纲期 episode 可无 plan_id，Demo 以
  `outline` 徽标呈现该前态）；`hook` 集尾悬念是短剧留存关键，大纲阶段显式编辑。
- **持久化**：`storage/series/{id}/series.json` + `characters/{cid}/` 参考图；
  原子写 + OS 锁沿用 `video_project.py` `_atomic_json`（L61）/`_lock`（L75）惯例。

### 4.2 分镜层 ScriptPlan（每集一份，向下兼容单视频任务）

```json
{
  "plan_version": 1, "revision": 3, "status": "draft|confirmed",
  "series_id": null, "episode_id": null,
  "title": "...", "logline": "...",
  "style": { "tone": "...", "palette": "...", "camera": "...", "consistency_subject": "..." },
  "target_duration": 60, "aspect": "9:16",
  "quality_tier": "draft|final",
  "voice": { "name": "...", "rate": 1.0 },
  "bgm": { "type": "random|acestep_local|provider|custom", "mood": "...", "prompt": "...",

  "llm": { "provider": "ollama", "model": "gemma4:26b" },
  "seed": 12345,

```

- `series_id`/`episode_id` 可为 null——**单视频任务（快速模式升级用法）同样持有 plan**，
  系列层是可选增强而非前置条件。
- `quality_tier`：draft=turbo 4-step 768p / final=完整模型（可接 UltimateSDUpscale），
  逐场景生成与关键帧生成共用档位。
- `bgm.type="acestep_local"`：本地 ACE-Step 按 `mood/prompt` 作曲（§5.2）；
  `random/provider/custom` 三态与现有 BGM 契约完全兼容。
- `llm`：方案生成所用 provider/model 记录在案，可追溯可复现（默认 ollama + gemma4:26b）。

方案层全局字段表：

| 字段 | 类型/枚举 | 语义 |
| --- | --- | --- |
| `plan_version` / `revision` | int×2 | schema 版本 / 修订号（每次人工或 AI 修改递增，确认时冻结） |
| `status` | draft / confirmed | 确认门禁：confirmed 才允许付费生成 |

### 4.3 场景层 Scene

```json
{
  "id": "s1", "order": 1, "locked": false,
  "speaker": "narrator|c1", "narration": "旁白/对白文本",
  "est_duration": 9.5, "measured_duration": null,
  "visual": "画面描述（AI prompt 基底）", "keywords": ["night city", "running"],
  "characters": ["c1"], "location": "l1",
  "relation_to_prev": "establish|continue|contrast|escalate|match_cut",
  "relation_note": "与上一段的关联说明",
  "engine": "local_fl2v|local_i2v|stock|cloud_ai",
  "material": { "source": "pexels", "candidates": [], "selected": null, "in": 0, "out": 5 },
  "keyframe": { "first": null, "last": null, "first_prompt": "...", "last_prompt": "...",
                "shared_with_prev": true },
  "transition_to_next": "none|fade|slide|zoom|match_cut",
  "subtitle_cues": null,
  "boundary_health": "ok|warn|unknown",
  "cost": { "tier": "free|paid", "estimate_cny": 0, "request_key": null }
}
```

字段要点：

| 字段 | 语义与约束 |
| --- | --- |
| `speaker` | v1 恒 narrator（旁白驱动）；B6 多音色对白模式按角色 id 路由 `voice_name` |
| `est_duration` / `measured_duration` | 估算 = 旁白字数 ÷ 4.2（中文语速）；实测 = TTS cues 切窗回填，生成前为 null |
| `characters` / `location` | 引用系列层资产 id；关键帧生成时注入对应参考图与场景 prompt |
| `relation_to_prev` + `relation_note` | 语义关联标注，库存源"可解释衔接"的核心；拖拽调序后受影响区间自动置 `unknown` 待复核（枚举含 unknown 态） |
| `engine` | 逐场景四选一：`local_fl2v`=本地·首尾帧动画化（MiniMax H3），`local_i2v`=本地·图生视频，`stock`=库存检索，`cloud_ai`=云端 AI（付费）；离线引擎置灰 |
| `keyframe.shared_with_prev` | **共享边界帧**：本段首帧 = 上段尾帧（同一文件），FL2V 条件化的像素级衔接；仅相邻两段均为本地引擎时有效，调序/换引擎后重算 |
| `material.in/out` | 库存素材入出点；改动后 `boundary_health` 置 unknown 待审查 |
| `cost.request_key` | 画面请求指纹（prompt+参数+模型包 sha1）；命中缓存直接复用，Demo 以 FNV-1a 模拟 |
| `subtitle_cues` | 预估 cue 数（≈字数÷12），执行后回填真实 SRT 区间引用 |
| `boundary_health` | ok/warn/unknown 三态；本地共享帧默认 ok，库存切点默认 unknown/warn，审查后落定 |

### 4.4 校验规则与持久化

- scene/character id 稳定：重生成保留 id；order 连续；locked 段 AI 不得覆盖（重生成跳过并记日志）。
- `est_duration` 总和与 `target_duration` 做 ±10% 容差校验，超差仪表变色 + 警告，不阻塞编辑。
- **边界帧共享约束**：`shared_with_prev=true` 时本段 `keyframe.first` 必须引用上一段
  `keyframe.last` 的同一文件（Demo 种子即按此构造：s2.first="ep2-s1-l"）；违反即校验失败。
- 未知字段拒绝（fail-closed，对齐 `video_project` 惯例）；导入文件须带
  `schema: "mpt.script_plan"` 包装或裸 plan，`plan_version === 1` 且 scenes 为数组才接受。
- 持久化：任务目录 `script-plan.json` 经 `task_artifacts` 写入；`script.json` 增加
  `plan_revision` / `series_id` 引用；系列层落 `storage/series/{id}/series.json`（§4.1）。

### 5.1 方案生成（本地 LLM 优先）

- 新阶段 `stop_at="plan"`：`_run_pipeline`（task.py L1971）在 script 之后插入；
  `llm.generate_script_plan()` 复用 `_generate_response` + `_strip_code_fence`（L1010）+
  `_extract_embedded_json`（L1026），**默认 provider=ollama**（已原生支持，推荐
  gemma4:26b / gpt-oss:20b）；Ollama 路径传 `format:"json"` 约束结构化输出，
  解析失败→修复重试→**降级为 legacy 扁平脚本**（快速模式不受影响）。
- **分阶段 prompt**：故事大纲→角色抽取→分集→分镜（借鉴多智能体编剧流水线，但单 provider
  顺序调用，不引 agent 框架）；每阶段注入系列 style_bible + 角色 appearance_prompt +
  上一集 hook，保证跨集连贯。
- **llama.cpp**：llama-server OpenAI-compatible 端点，按 Registry 注释（llm_provider.py
  L192–194）新增一条 `llamacpp` 注册项 + 14 locale；或经既有 OneAPI/LiteLLM 网关零代码接入。
  端口待用户确认（§1b 开放项），不阻塞 Ollama 主路径。
- 方案确认门禁：`status != confirmed` 时付费引擎场景拒绝进入生成；免费本地场景可预览生成。

### 5.2 本地 provider 层（新增 Python 服务模块，移植 ChangoVideo 已验证契约）

- **`app/services/comfy_local.py`**：裸 origin `http://127.0.0.1:8188`（config 可覆盖，
  兼容 comfy-mini 8190 代理）；graph 构建器移植 comfy-mini `app.py`（t2i L172 起步）+ 新增
  **MiniMax H3 FL2V graph**（first/last image 条件 + turbo LoRA 档位 + video/audio VAE）与
  **IPAdapter 角色参考 graph**；模型=成套参数包（小白不碰节点）；FNV-1a/sha1 确定性 seed；
  `/prompt` 提交 + `/history` 轮询 + WS `progress_state`×节点权重折算 0–100%
  （KSampler=steps×10，断线静默降级轮询）；提交后 `GET /queue` 播报排队深度；
  **sha1 requestKey 内容寻址复用**（同 prompt+参数+模型包→直接返回已有产物，
  跨任务共享缓存目录，`.key` 旁车存指纹与去计费回执）。
- **`app/services/acestep_local.py`**：移植 acestep.mjs 契约（127.0.0.1:8001，300s 预热等待 +
  可重试错误文案，**绝不触发 uv sync**）；按 `plan.bgm.mood/prompt` 生成每集主题曲，
  复用既有 `bgm.validate_audio_file` 长轨校验与 `bgm_file_override` 三态契约
  （provider 产出绝对路径→跳过 AudioLoop）。
- **健康探测**：`GET /system_stats`（ComfyUI）、`/health`（ACE-Step）、`/api/tags`（Ollama）
  → 统一 `local_engines_status()` 供 UI 就绪度仪表盘与 preflight 复用；离线时场景引擎
  选择器自动置灰并提示降级到库存/云端。

### 5.3 方案→执行编译器与关键帧链（连续性核心）

- confirmed plan 编译为**逐场景素材请求**（keywords/characters/location 绑定场景，替代全局
  terms 轮询）+ 显式时间线；`combine_videos`（video.py L987）增加可选 `timeline` 参数
  （场景→素材 in/out 序列），缺省 None 走原逻辑——最小侵入，快速模式零回归。
  转场取 `scene.transition_to_next`，不再按片段 RNG 随机。
- **本地关键帧链（主路线，四步）**：
  ① 按 `scene.keyframe.first_prompt/last_prompt` + 角色 `reference_images`（IPAdapter）+
  style_bible 生成关键帧对（t2i）；
  ② `shared_with_prev` 场景直接复用上一段尾帧文件作首帧；
  ③ MiniMax H3 FL2V 在首尾帧间动画化→**场景内部与场景边界像素连续均由模型保证**；
  ④ 草稿档 turbo 4-step 768p，成片档完整模型（可接 UltimateSDUpscale）。
- **云端关键帧链（保留升级项）**：ffmpeg 抽取已选片段首/尾帧→尾帧作为下一段 seedance/muapi
  图生视频首帧条件（seedance payload content 追加 `{"type":"image_url",...}`，L279 处扩展）；
  首帧图可由 openai_image/codex_image 既有 provider 按 prompt 生成。
- **库存源**：不承诺像素连续；语义关联标注 + 切点审查 + 转场遮蔽三层（§2.1 纠偏 3）。

### 5.4 TTS 对齐与时长回填

整篇旁白**一次 TTS**（保留现有 pause markers / 单 sub_maker 契约），用 cues 时间戳按
场景旁白字符边界切分场景时间窗；`measured_duration` 逐场景回填，`subtitle_cues` 回填真实
SRT 区间。**旁白主路径不做逐场景独立 TTS**（破坏现有时间轴，§9 ②）。总时长超差 ±10% 时
经现有 warnings 通路提示，不自动拉伸/截断画面。
**多音色对白模式**（`speaker` 字段路由不同 `voice_name`、逐句 TTS 拼接 + 独立时间轴装配器）
列为 B6 独立模式，不破坏旁白驱动主路径。

### 5.5 边界审查

`review.py` 新增 finding code `scene_boundary_jump`：切点前后帧差 + 亮度/色度突变检测
（沿用已校准的 yuv420p luma 阈值经验），finding 携带场景 order，经现有 warnings 通路
surfaced，零新状态字段。本地 FL2V 共享帧场景预期恒 ok——审查作为**回归哨兵**而非主手段；
库存切点是主要告警来源。

### 5.6 成本与队列

本地引擎**单 GPU 串行**（与 MPT 既有全局串行队列哲学一致），场景级进度复用
`generation_progress`；每场景 cost 徽标汇总到生成前确认页（本地免费项 vs 云端付费项分列，
付费场景强制确认模态）。ComfyUI 提交前健康检查 + `/queue` 感知，避免与用户其他 ComfyUI
任务显存互斥（§8）。

### 5.7 增量重渲染（后置批次）

plan 编译为 video_project scene spec，复用 `stage_graph`（L171–243）指纹——改一段只重渲一段。
前置条件：video_project 补字幕/转场能力（其文档 L82–84 明确当前不支持），列为独立批次
B8，不阻塞主路径。

| 编剧引擎离线 | [AI 生成方案] 降级为模板方案 | 日志明示"快速模式不受影响" |
| 画面引擎离线 | [本地生成关键帧] 置灰 + 提示 | 可改选云端付费源（强制确认）或库存 |

方案/剧集生命周期状态机（Demo 已实现同构语义）：

```
方案：  (无) ─AI生成/导入→ draft ─人工编辑→ draft(revision++)
                     └─确认→ confirmed ─生成完成→ 实测回填（仍 confirmed）
                     confirmed ─再编辑→ draft(revision++)（付费门禁重新生效）
剧集：  outline ─分镜生成→ draft ─方案确认→ confirmed ─渲染完成→ rendered
锁定：  生成期间 plan 页入 LOCK_PAGES；complete 任务另存为新草稿不覆盖旧成片
```

交互表（Demo 全部以 delegated `data-action` / `data-bind` 实现）：

| 交互 | 行为 | 状态联动 |
| --- | --- | --- |
| 编辑旁白 | 局部 DOM 更新，est=字数÷4.2 | 时长徽标 + 总时长仪表 + 时间线色块比例实时联动 |
| 编辑预估时长 | clamp 2–60s | 仪表超 ±10% 容差变色（over 态） |
| 锁定开关 | locked=true/false | AI 重生成跳过该段并记 warn 日志；卡片琥珀锁定态 |
| 拖拽重排 | 卡片/时间线色块 HTML5 draggable | order 重编号；受影响区间 relation→unknown、**共享帧关系同步重算**；revision++ |
| 引擎切换 | 逐场景四选一 | 离线引擎置灰；成本徽标重算；库存自动补候选；边界健康重算 |
| 档位切换 | draft/final 分段按钮 | 关键帧/视频生成步数与分辨率联动（4步768p ↔ 完整1080p） |
| AI 生成方案 | 模拟 Ollama 流式（离线降级模板） | 逐场景渐进出现 + 方案生成日志；locked 段保留 |
| 重生成此段 | 保留 id/order/locked，换文案变体与新帧种子 | revision++、status→draft、request_key 清空 |
| 换素材/选候选 | 候选轮换 / 画廊点选 | selected 更新，入出点保留 |
| 本地生成关键帧 | queue 播报→KSampler 步进度（draft 4 / final 8 步） | 帧 SVG 更新 + requestKey 签发；同参复用走缓存快路径 |
| 转场选择 | none/fade/slide/zoom/match_cut | 连接器与生成日志逐转场行联动 |
| 导出/导入 | 真实 JSON 下载（schema 包装）/ 文件导入校验还原 | 导入失败 toast；成功 revision++ |
| 确认方案并生成 | 校验旁白非空/引擎在线→付费场景弹确认模态 | status→confirmed；生成引擎按场景输出日志；完成后实测/cues/边界回填，剧集→rendered |

状态覆盖：

- **空方案**：引导文案 + CTA[用 AI 生成一份方案]。
- **生成中**：流式日志逐场景推进，含 ComfyUI 排队位置 / KSampler 步数进度 / ACE-Step 预热提示；
  故事板渐进揭示（已生成场景先出现）。
- **已确认锁定**：LOCK_PAGES 纳入 plan 页，生成期间编辑控件锁定。
- **失败降级**：引擎离线提示 + [降级为库存素材] 一键操作；付费确认模态（场景数×单价汇总）。
- **生成引擎联动**：confirmed plan 存在时 `buildSteps` 按场景输出日志
  （"场景 2/6 本地首尾帧动画化…"），结果区逐场景回执。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 本地模型 JSON 输出不稳定（26B 模型偶发畸形） | plan 生成失败 | **format:json + 修复重试 + 降级 legacy 三层**；fail-closed 校验拒绝未知字段 |
| 单 GPU 串行排队时长 | 多集系列生成等待长 | 草稿档 4-step 先看效果 + `/queue` 队列深度播报 + 可取消；与 MPT 全局串行队列哲学一致 |
| MiniMax H3 显存占用与 ComfyUI 其他任务互斥 | OOM / 用户任务被挤掉 | `/queue` 感知 + 提交前健康检查（`/system_stats` 显存余量）；int8/pruned 权重双档可选 |
| ACE-Step 预热 300s | 首单超时 | 可重试错误文案（"服务可能正在加载模型，请稍后重试"），**不阻塞分镜阶段**；eager load 启动 bat 已落地；超时降级随机曲库 warn |
| 角色一致性漂移 | 短剧系列"主角换脸" | 参考图固定 seed + IPAdapter 强度参数包化 + 人工锁定门禁；v1 明示免训练能力边界（§2.1 纠偏 4） |
| llama.cpp 端口未确认 | 后备编剧引擎不可用 | 文档列为**待用户确认项**，不阻塞 Ollama 主路径；接入仅需一条 Registry 项 |
| TTS 语速浮动导致总时长超差 | 用户预期落差 | ±10% 容差仪表前置可见 + 实测回填 + 超差警告，不静默拉伸 |
| 库存切点突变 | "莫名其妙"观感残留 | 语义标注前置 + scene_boundary_jump 审查 + 转场遮蔽三层；不承诺像素连续 |
| 双轨模式增加维护面 | 简单/专业行为分叉 | 简单模式仅是导航过滤+向导入口，底层同一 state/引擎；验证套件双模式都跑 |

## 9. 拒绝的替代方案

1. **节点图 UI（ComfyUI 式）**：每个决策可见的思想借鉴，但节点连线画布的学习成本与
   小白用户群根本错配；分镜卡片 IA + 表单化参数包以 1/10 的学习成本覆盖同等表达力。
2. **旁白主路径逐场景独立 TTS**：破坏现有单 sub_maker 时间轴与 pause markers 契约，
   字幕/音频对齐全部重写；整篇一次 TTS + cue 切窗以零契约破坏达成同等场景时长精度。
   多音色对白作为独立模式（B6 独立时间轴装配器）另行设计，不混入主路径。
3. **一步替换 combine_videos 为 video_project 渲染**：后者当前无字幕/转场能力
   （docs/video-projects.md L82–84），一步替换=功能回退；timeline 可选参数最小侵入，
   增量渲染列为 B8 后置。
4. **引入 OpenFilm 浏览器渲染器**：Node+Chromium 运行时重量与 Python 栈冲突，违背既有
   融合路线 A→C→B 渐进决策；声明式时间线/确定性/双层校验思想以 Python 侧等价物吸收。
5. **库存素材像素级首尾帧承诺**：不同来源素材物理上不可能像素连续，承诺即欺诈；
   改为语义关联+边界审查+转场遮蔽三层，并在 UI 明示库存切点的 warn 语义。
6. **云端付费源为默认**：按场景付费使 60s×多集系列成本不可控，违背低成本目标；
   本地优先（零边际成本），云端仅作逐场景可选升级项 + 强制付费确认。
7. **v1 角色 LoRA 训练**：每角色训练数十分钟起步、数据准备门槛高，与"几分钟出预览"的
   小白体验冲突；免训练参考图 + IPAdapter + 固定 seed 路线先行，LoRA 仅作预留挂载点。
8. **无限画布（novelvids 式）**：自由画布对小白是空白恐惧，对批量自动化用户是操作负担；
   向导五步 + 卡片流 + 结构化故事板替代，资产化工作流思想保留。
