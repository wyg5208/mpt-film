### 痛点

1. **垂直四段堆叠**：标题导航、四卡片、预设/生成、日志结果依次纵排，1080p 视口下生成按钮与日志首屏不可见，用户反复上下滚动。
2. **四等宽卡片浪费宽度**：每列约 300–360px，长标签（如"同时生成视频数量"）折行；1500px 以下退化为 2×2 后页面更长。
3. **日志与编辑互斥**：日志在页面最底部，改参数时看不到进度；任务管理藏在 popover 里，发布历史再藏一层 tab。
4. **设置层次过深**：大模型、素材 Key、发布渠道是每次创作都可能要动的配置，却埋在"设置弹窗 → tab → 分组"三层之下。

## 2. 完善后的需求

### 2.1 布局壳

- **顶部栏（48px，固定）**：品牌 + 版本、运行中任务数徽标、**居中当前项目切换器（v2）**、语言切换（zh/en）、主题切换（深色默认/浅色）、设置快捷入口。除项目切换器外不放业务控件。
- **左侧菜单（展开 232px ↔ 收起 64px 图标栏）**：向左收起；收起后保留图标 + tooltip + 激活指示条；状态持久化（Demo 用 localStorage，生产用 `st.session_state` + `config.ui`）。
- **中间功能页（弹性宽度）**：每个菜单项一页；页内用多列网格充分利用宽度，1440–1920px 视口整页工作流一屏可见，只有内部列表/日志滚动。
- **右侧生成面板（展开 380px ↔ 收起 48px 竖条）**：向右收起；收起竖条显示"生成日志"竖排文字 + 实时状态点/徽标（运行中 %、完成 ✓、失败 !）。展开自上而下：任务状态卡（阶段 chip、进度条、已用时）→ 流式日志（等宽字体、时间戳、按级别着色、自动滚动 + "回到最新"）→ 结果区（成片卡片、下载、审查警告）。
- **中列底部常驻操作栏（每页可见）**：主按钮"生成视频"（运行中 busy 态）、设置预设导出/导入、就绪度摘要 chips（来源/配音/字幕/数量）。解决"滚到底才能生成"。
- 收起快捷键 `Ctrl+B`（左）/ `Ctrl+J`（右）；过渡 ≤200ms；中列内容不跳动。

### 2.4 项目与参数绑定（v2 迭代）

**问题**：旧版单页中，文案/视频/音频/字幕参数与生成日志同屏，天然绑定"当前项目"；菜单式拆页后，参数散落在多页，缺少"当前项目 ↔ 参数"的绑定、项目加载入口与设置预设功能。

**核心模型（对用户建议的关键优化）：项目 = 任务记录，单一数据源。** 不引入并行的"项目"存储：每个任务记录携带唯一 `id` + 完整参数快照 `params` + 状态（`draft 草稿 / processing 生成中 / complete 已完成 / failed 失败`）+ `updatedAt`。`currentProjectId` 指向任务表中的一条记录；顶栏切换器、任务表"加载"、生成引擎读写的是**同一条记录**。生成时复用当前项目 id（而非新建任务），任务状态原地流转 processing→complete/failed，参数快照随之落库——这使"已生成任务锁定参数"与"项目切换"天然一致，避免两套 id 映射。

## 3. 生产迁移方案（推荐：方案 C，两阶段）

### 3.1 Phase 1 —— 三列壳（零逻辑改动）

```python
# _render_application 内
left_w = 64 if st.session_state.get("nav_collapsed") else 232
right_w = 48 if st.session_state.get("log_collapsed") else 380
nav_col, page_col, log_col = st.columns([left_w, "stretch", right_w], key="app_shell")
```

- Streamlit 1.66.1 的 `st.columns` 只接受数值权重，**不支持像素列宽**（v3 实测修正）：像素宽由 styles.css 依据 `app_shell_n*_l*_m*` 状态键锁定（232/64、380/48），收起/展开不依赖运行时测量。
- **左列**：导航按钮组，点击写 `st.session_state["active_page"]`；底部收起切换按钮。
- **中列**：每页一个带 key 容器（`st.container(key="page_script")` 等），作为 `panel` 参数传给**原样不动**的 `_render_script_settings / _render_video_settings / _render_audio_settings / _render_subtitle_settings`。四个渲染函数每次 rerun 全部执行，非激活页用 `display:none` 隐藏——沿用 styles.css 既有 `st-key-*` 选择器约定：外层再包 `st.container(key=f"active_page_{active}")`，CSS 形如
  `div[class*="st-key-active_page_script"] div[class*="st-key-page_script"] { display:block }`，其余默认 none。
- **右列**：`_render_generation_controls` + `_render_current_generation_task`（0.5s fragment 原样）。生成按钮移入中列底部常驻容器，`_render_settings_transfer` 随迁。
- 收起切换翻转列宽为 `[64, "stretch", 48]` + 竖条 CSS；偏好持久化到 `config.ui`。

**为什么安全**：params 装配、widget key、回调、计费确认 session 守卫、上传暂存、日志 fragment 全部字节级不变；隐藏页的 widget 仍每次渲染，Streamlit 的 widget-state 清理不会丢值。

### 3.2 Phase 2 —— 菜单提升

- 从 `_render_settings_dialog` 抽出 LLM/素材/发布三个 tab 体为独立页面渲染函数（它们本就向传入 panel 渲染）。**弹窗 7 个 tab 原样保留**（v3 修正：AppTest 契约断言弹窗 tab 数）；提升页与弹窗共用渲染函数，弹窗打开时一级页让位避免重复键。
- `_render_task_manager_panel` 已接受容器参数，直接成为任务管理页；发布历史 tab 独立成页。
- 重新锚定 `streamlit_tour` 引导步骤。

### 3.3 验证计划（未来生产迭代）

- 按仓库约定做基线失败差分：`.venv\Scripts\python.exe -X utf8 -m pytest`，改动前后 Compare-Object 比对失败集合（约 50 个字体/环境既有失败）。
- 浏览器 5 视口检查；确认 fragment 轮询不受布局影响；生成→日志→成片全链路。

### 3.4 项目绑定的生产映射（v2，Phase 3）

- **存储**：任务记录已有 `storage/tasks/<id>/` 目录与元数据；为每条任务增加 `params.json`（完整 VideoParams 快照，生成提交时写入）。`st.session_state["current_project_id"]` 指向任务 id；加载 = 读快照回填 widget key 对应的 session 值后 `st.rerun()`。
- **脏检测**：加载/保存时对 params 快照做规范化 JSON 基线；**run 末尾**比对上一 run 快照置脏（v3 修正：Streamlit 回调拿不到组装后的完整 params，on_change 逐控件比对不可行）；切换项目前用 `st.dialog` 呈现三选确认（保存并切换/放弃/取消）。
- **锁定**：任务目录存在 `final-<n>.<ext>` 即 complete → 锁横幅 + CSS `:has()` 锚定横幅对创作区置 pointer-events:none/降饱和 + 生成按钮服务端 disabled + "另存为新任务"按钮（克隆 params.json 到新任务目录）。**Streamlit 无容器级 disabled**（v3 实测修正）。全局配置页不受影响。
- **预设库**：`storage/presets/<uuid>.json`，**复用既有 `moneyprinterturbo.settings-preset` v1 schema**（v3 修正：不另立 mpt.param_preset，与设置导出文件互通），额外携带 name/saved_at；入库前剥离密钥与上传暂存路径（沿用 PRESET_EXCLUDED_PARAM_KEYS）；内置 4 预设为代码常量不落盘；`_render_settings_transfer` 的导出导入逻辑直接复用。
- **风险**：Streamlit widget-state 清理与快照回填的时序（须在渲染前写 session 值）；上传文件类参数不随快照迁移，加载后需提示重新上传。

| 方案 | 否决原因 |
| --- | --- |
| A：`st.navigation` 多页拆分 | 万行单体中 params 装配与数十个回调假设四面板同 run 渲染；Streamlit 会清理未渲染 widget 的 session 值，静默丢参风险高。可作为 C 之后的远期演化 |
| B：只渲染激活页 + 纯函数 `assemble_params()` | 约 60 个 param 字段（计费确认、上传暂存、loomloom 报价、试听复用）有意会话域内存在于渲染函数中；影子持久层会引入只在生成时暴露的参数漂移 |
| 本次直接改 Main.py | 用户要的是需求+方案+Demo；先用低成本 Demo 验证 IA，符合本工作区 Demo 先行惯例 |
| React/Vite Demo | 为一次性设计产物引入工具链；纯 HTML/CSS/JS 可 file:// 直开、人人可评审 |

## 5. 风险登记

- Demo 与真实功能漂移 → 每页控件逐一对照 Main.py 渲染函数与 zh.json 标签枚举。
- Streamlit 升级破坏 CSS 隐藏约定 → 钉版 1.66.1；升级时回归 `st-key-*` 选择器。
- 隐藏面板仍执行逻辑（LLM 就绪读取等）→ 与现状成本一致，均有缓存；远期再评估方案 B。
- 移动端 fragment 与浮层叠加 → 浮层 z-index 高于 fragment 容器，Esc/遮罩关闭。

## 6. Demo 使用说明

浏览器打开 `docs/ui-redesign-demo/index.html`（或任意静态服务器）。深色默认，可切浅色/英文；左右栏可收起（Ctrl+B / Ctrl+J）；文案页填主题后点底部"生成视频"，右栏演示完整阶段日志流与成片结果；字幕页控件实时驱动手机框预览；任务管理支持筛选/搜索/撤销删除，点击标题或"加载"回填参数；预设可导出导入真实 JSON。

## 7. 生产实施结果（v3，2026-11-20）

迁移已按方案 C 在 `webui/Main.py` + `webui/styles.css` 执行完毕，三个 Phase 全量落地；四个创作渲染函数、params 装配、回调、计费确认守卫、上传暂存与 0.5s 日志 fragment 字节级未动。

### 7.1 落地机制

- **壳**：`st.columns` 数值权重 + `app_shell_n{232|64}_l{380|48}_m{0|1}_o{0|1}` 状态键，像素宽与收起/浮层/竖轨形态全部由 styles.css 锁定；偏好持久化 `config.ui`；`Ctrl+B`/`Ctrl+J` 快捷键；中列底部常驻操作栏（生成按钮 + 设置预设导入导出 + 就绪 chips）。
- **页**：`NAV_PAGES` 11 项；`active_page_*` 外层容器 + `page_*` 内层容器的 CSS 显隐约定（四渲染函数每 rerun 全执行）；LLM/素材/发布三页与设置弹窗共用渲染函数，弹窗打开时一级页让位避免重复键（弹窗 7 tab 原样保留）；任务管理、发布历史独立成页。
- **绑定**：`storage/tasks/<id>/params.json`（`moneyprinterturbo.project-params` v1）；`current_project_id` 会话指向；脏检测 = run 末尾快照与基线比对；切换/新建前三选 `st.dialog`；顶栏切换器 popover 每批 20 + 加载更多 + 新建空白，候选期间 epoch 键重挂载避免 portal 盖弹窗；保存后 `st.rerun(scope="app")` 消琥珀点。
- **锁定**：任务目录存在 `final-<n>.<ext>` 即 complete → 锁横幅 + `:has()` 锚定创作区 pointer-events:none/降饱和 + 生成按钮服务端 disabled + “另存为新任务”克隆 params.json 到新 uuid 目录。
- **预设库**：`storage/presets/<uuid>.json` 复用 `moneyprinterturbo.settings-preset` v1 schema（+name/saved_at）；内置 4 预设为代码常量 `BUILTIN_PRESETS` 不落盘；存为预设/导入/单个导出/删除/一键应用齐备，脏时应用走三选确认、锁定项目拒绝应用；入库剥离 `PRESET_EXCLUDED_PARAM_KEYS`。
- **i18n**：新增键全部写入 zh/en；预设页 30 键走 `ENGLISH_FALLBACK_KEYS` 英文兜底契约；`utils.load_locales` 带 lru_cache，增键后需重启服务。

### 7.3 验证期发现并修复的真实缺陷

1. **首屏浮层盖顶栏**：`config.ui` 无收起键时默认展开，≤1500px 的 fixed 右浮层（top:0/z120）首屏即遮住顶栏项目切换器/设置/语言。修复：761–1500 band 自动收为 48px sticky 竖轨 + 会话标记 `log_overlay_user_open`（壳键 `_o` 后缀）；竖轨上普通切换按钮语义是“收起”（死按钮），故新增专用 `log_overlay_open_button`（仅 band 内可见）承担展开。回归断言 verify-shell 6.1b。
2. **竖轨空轨**：`st-key-*` 类就在 `stElementContainer` 自身上，`:not(:has([class~=st-key-X]))` 锚不到自己导致竖轨所有按钮被隐藏；改 `:not([class~=…])` 直接类匹配。
3. **预设保存栏窄屏换行**：水平容器子项 flex-basis:auto + wrap 先换行再收缩；改 `flex-wrap:nowrap` + 输入框 `flex:1 1 0`，限宽落在 stElementContainer 包装层。
4. **任务页惰性渲染破坏 popover 契约**：Phase 2 初版任务管理/发布历史仅激活时渲染，而旧顶栏 popover 每次 rerun 都渲染行级按钮（headless 回归测试在默认 run 直接寻键 `play_task_all_*`/`open_task_all_*`）→ StopIteration。修复：两页改回每次 rerun 全量渲染（`page_tasks`/`page_publish_history` 容器 + CSS 显隐约定，与创作页同构），2s fragment 成本与旧 popover 等价。

（另有几处 harness 侧适配，非产品缺陷：`localized_widget_key` 使 widget 键带语言后缀需前缀选择器；1.66 selectbox 为 react-aria ComboBox，取值读 `input[role=combobox].value`；全量渲染后 DOM 流式到达，固定 sleep 会赛跑，改元素级等待；`waitForSelector` 默认 visible 取首个匹配，首匹配被 CSS 隐藏时假超时，改 `waitForFunction` 断言“任一可见”或可见过滤定位器。）

**验证卫生教训**：AppTest 交互（set_value/click）只排队、下次 `.run()` 才重跑，故读盘配置类测试的首 run 状态取决于 config.toml 现值；自研 AppTest 检查脚本必须与真测试一样 patch `config.try_save_config`，否则会把验证期参数写进开发者真实配置，造成后续套件假失败。全量 pytest 在本机偶发 Windows access violation（Streamlit magic AST 递归），按 head/tail 文件分块复跑合并失败集判定。
