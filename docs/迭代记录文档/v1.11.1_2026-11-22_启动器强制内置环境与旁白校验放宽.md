# 2026-11-22 迭代记录（v1.11.1）：启动器强制内置环境与旁白校验放宽

本轮为缺陷修复驱动型迭代，是同一天继 v1.11.0（侧边栏精简与浅色主题）之后的
第二批修订，三件事都由用户实测反馈驱动：**webui.bat 会回落到电脑全局环境**
（用户明确要求"改成系统内置 python 虚拟环境，不要使用电脑环境"）、**专业短剧
点「确认方案并生成」被"每个场景都需要旁白"拦死**（用户指出该拦截不合理）、
**快速成片点生成无反应**（诊断为付费确认复选框会话态重置，非代码缺陷）。

核心技术结论：旁白逐场景必填的守卫与本项目下游编译器的既有设计直接矛盾——
`app/services/plan_compiler.py` 从设计上就允许空旁白场景（跳过文本、画面仍占
时间窗、支持全空均分的哑剧场景），且 `test/services/test_plan_compiler.py` 早
有中间场景空旁白的通过用例。守卫真正的下限只是"整篇旁白全空则无可读 TTS 内容"，
故本轮把条件从"每个场景都必须有"放宽为"至少一个场景有"，属行为修正而非新增能力。

本轮无任何新功能，按版本政策升 **patch：`v1.11.0 → v1.11.1`**。

## 2. 变更清单

### 2.1 webui.bat 强制使用项目内置解释器（对应提交批次 A：启动器加固）

- `webui.bat`（L16-33 解释器解析块）：删除两条面向电脑全局环境的回落路径
  ——`where uv` + `uv run streamlit` 整块、`where streamlit` + PATH `streamlit`
  整块（连带其 warning 提示一并移除）。现在只保留两条项目内置路径，顺序不变：
  1. `%CURRENT_DIR%\.venv\Scripts\python.exe -m streamlit`（项目虚拟环境）
  2. `%CURRENT_DIR%\lib\python\python.exe -m streamlit`（项目内置打包运行时）
- 两者都不存在时不再向外找：输出
  `***** No project virtual environment found. Create it first with: uv sync --frozen *****`
  → `pause` → `exit /b 1`（旧文案 `Neither project Python, uv, nor streamlit was
  found. Please install dependencies first.` 随之作废，测试 docstring 同步改写）。
- 新增五行 `rem` 说明块，写明"绝不下沉到 `uv run` 或 PATH streamlit——它们按机器
  环境解析，会拿本项目未 pin 的包跑应用"，把该约束固化为文档化契约，防止后人
  再把回落加回来。
- 未改动：端口解析（`webui_port.ps1`，L35-53）、host 归一化与 `0.0.0.0` →
  `127.0.0.1` 的浏览器地址处理（L56-58）、`cd /d "%~dp0"` 项目目录解析。
  "仅对 python.exe 路径加引号"的既有写法保留（引号包住整个赋值会让路径本身失引号，
  路径含 `)` 或 `&` 时击穿该块）。

### 2.2 旁白校验放宽（对应提交批次 B：缺陷修复）

- `webui/Main.py`（约 L12197-12204，`_render_plan_page()` 的 `execute_clicked` 分支）：
  守卫条件由

  ```python
  if any(not scene.narration.strip() for scene in plan.scenes):   # 旧：逐场景必填
  ```

  改为

  ```python
  if not any(scene.narration.strip() for scene in plan.scenes):   # 新：至少一个场景
  ```

  即只在**整篇无任何旁白**时拦截；附四行中文注释解释设计口径：静音空镜合法
  （编译器跳过空旁白场景、画面仍占时间窗），但旁白走一次整篇 TTS，全空则无可读
  内容、`task.py` 音频阶段必然失败，故下限是"至少一个场景有旁白"。
- 放宽的事实依据（Grep/Read 逐处核实，均本轮改动前既存在库）：
  - `app/services/plan_compiler.py::plan_to_script`（L32-36）docstring 明写
    "空旁白场景跳过（画面仍占时间窗）"，实现即 `if scene.narration.strip()` 过滤。
  - `build_scene_windows`（L150-153）`total == 0` 分支注释"全部空旁白：均分时间窗
    （画面哑剧场景）"——全空方案本身是可编译的。
  - `build_project_request`（L268-271）`if scene.narration.strip() and not audio:`
    才要求配音音频，即空旁白场景不要求音频。
  - `test/services/test_plan_compiler.py`：`TestPlanToScript::
    test_joins_non_empty_narrations_in_order`（中间场景 `s2` 空旁白，通过）、
    `test_all_empty_narration_splits_equally`、
    `test_all_empty_narration_yields_empty_script`（正是"全空无可读内容"这一真实下限的写照）。
- 文案 `webui/i18n/*.json`：**13 个**语言文件（zh/en/id/es/ca/az/ko/ru/fr/pt/de/vi/tr）
  的 `"Plan Narration Required"` **value** 更新为"至少一个场景需要旁白（并非每个镜头
  都必须）"语义，key、行位与文件结构不变。zh：「生成前至少需要一个场景填写旁白
  （并非每个镜头都必须有）。」；en：`At least one scene needs narration before
  generating (not every shot requires it).`
  - 由一次性脚本 `.tmp-ui-impl/update-narration-i18n.py`（gitignore，不入库）应用：
    逐文件断言 key 恰好命中一次，改写后回读校验 JSON 仍可解析。
  - 旧措辞残留复核：`git grep` 面向用户文案零命中（唯一命中为 `Main.py` 新注释里
    "而不是每个场景都必须有"这句解释性文字，非用户可见串）。

### 2.3 快速成片"生成无反应"诊断（无代码修改，对应批次 C：仅验证）

- 定位：`webui/Main.py` L11323-11328 —— `params.video_source == "metaso_minimax"`
  且 `st.session_state.get("metaso_minimax_confirm_charge", False)` 为假时，
  `_remove_active_generation_task(task_id)` + `st.error(tr("Confirm Metaso MiniMax
  Charge Required"))` + `st.stop()`。该复选框是会话级状态，不落 `config.toml`，
  页面刷新或服务重启后回到未勾选，故症状呈"重启后突然点不动"。
- 结论：拦截逻辑本身正确（付费源需显式确认），非缺陷；本轮不改代码，只做人工
  验证与口径说明。同族的 `muapi_confirm_charge`（L11337 起）、OFox 确认（L11311）
  是同一模式，用户遇到时同理。
- 处置：用户勾选付费确认后快速成片生成成功；专业短剧在新守卫下生成亦成功，
  双路线真人验证通过。

  `test_webui_launcher.py` 之外的 POSIX 侧验证），记为后续项。

  某些镜头旁白做静音空镜，但首稿仍应有完整旁白。本轮不动，避免一次改动同时

  说明正确入口是脚本方案 TAB 的「确认方案并生成」，按钮行为未改。后续应让该
  按钮在专业页上下文下不校验快速页字段，或改为直达方案页。
