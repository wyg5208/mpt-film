### 2.10 UI 加载稳定性修复（2026-11-21 补记，同属 v1.7.0 未发布批次）

用户反馈“网页总是重复加载、渲染和漂移”。排查定位三个空闲期周期性
重渲染源（render-all 壳的副作用）并修复，均在 `webui/Main.py`：

1. **隐藏页无条件轮询**：`_render_tasks_page` / `_render_publish_history_page`
   两个 `@st.fragment(run_every="2s")` 原先不管活动页是谁都每 2 秒重建
   任务面板（扫描至多 50 个任务目录 + 解析 script.json）与发布历史
   （重读 100 条）并替换隐藏节点。改为仅 `active_page` 命中时走 fragment，
   非活动时静态渲染同一面板（行级按钮每次 rerun 仍存在，headless 契约
   不变；面板内全是无状态按钮，切换不丢控件状态）。
2. **导航任务徽章空闲扫描**：新增 `_render_nav_tasks_entry` 分流——有处理中
   任务才启动 2s fragment；空闲静态渲染（计数每次整页 rerun 重算，外部
   创建的任务仍能捕获）。fragment 内计数归零时做一次整页刷新切回静态
   （批次完成时刻的有意义刷新）。
3. **版本检查启动漂移**：`_render_pending_version_check` 完成后不再
   `st.rerun(scope="app")`（那会在启动 1–3 秒后无请求地重渲整页、抢焦点/
   滚动）；改为 fragment 内直接渲染带徽章的品牌区，下次自然交互的整页
   rerun 改走静态停止轮询。

保留的合法轮询：生成日志 0.5s（仅生成期）、loomloom 2s（仅运行批次）、
引擎仪表盘 15s（仅 wizard/plan 活动页，TTL=15s 对齐）。

附带修复：`test_video_project_b8.py` 的 ffprobe 哨兵断言改为显式传入不存在
的二进制（原先依赖环境 PATH 无 ffprobe，全套件顺序变化时其他测试泄漏
`opensources/tools` 进 PATH 即假失败；已用污染 PATH 复跑验证免疫）。

门控契约 + AppTest 导航冒烟）。

### 2.11 创作路线引导层（2026-11-21 补记，同属 v1.7.0 未发布批次）

用户提问“文案设置页和脚本方案页什么关系？似乎没有关联”。核实结论：两者是
**两条创作路线**（快速：主题→AI 文案→库存素材；专业：向导→ScriptPlan→
逐场景执行），但共用同一条生成提交链路——`_render_generation_controls`
消费 `script_plan_execute_payload`，方案执行时覆盖标题/画幅/时长/音色，
BGM 与字幕仍沿用创作面板；任务运行期间两条路线的提交按钮均被
`_generation_is_busy` 禁用，**不会同时启动两条路线的生产**。UI 此前没有
