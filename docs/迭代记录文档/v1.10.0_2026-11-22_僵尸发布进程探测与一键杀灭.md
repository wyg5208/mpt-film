# 2026-11-22 迭代记录（v1.10.0）：僵尸发布进程探测与一键杀灭

本轮迭代为故障驱动型：重启/杀掉 WebUI 只终止 WebUI 本身，它派生的
sau.exe → node → chromium 发布进程树会变成**孤儿**继续后台上传——2026-11-19
的小红书僵尸任务实测遗留 **3 天、14 个进程**，同账号双开显著抬高平台风控概率。
用户要求："这种僵尸任务，能否通过桌面端的探测器提醒用户，用户可以通过按钮
直接杀灭"。本轮在外层仓库实现僵尸发布进程探测器服务 + 任务管理面板警示区
（单个/全部一键整树杀灭），**零新增 Python 依赖**，判定与杀灭全程贯彻
"宁可漏报/漏杀，不可误杀"纪律，并以真机端到端实证收口。

版本号按"每次迭代必升版"政策由 `1.9.0` 升至 **`1.10.0`**（minor：新增面向
用户的僵尸进程探测与清理功能）。本文档全部代码符号、测试数量与实证数据均于
当日 Grep/代码/测试核实（测试数量为本次文档生成时 pytest 实测重跑值）。

> **仓库边界**：本轮全部变更落在外层 ChangoFilm 仓库，**不涉及 bundled 子仓库
> `opensources/social-auto-upload` 的任何改动**。功能代码、测试、i18n、文档与
> 升版产物均未提交，待 `version-release` 以 `release: v1.10.0` 批次入库。

## 1. 故障与根因

| # | 场景 | 现象 | 根因 |
|---|------|------|------|
| 1 | 重启/杀掉 WebUI 后 | 上一代会话派生的 sau.exe 发布进程树仍在后台上传（实测遗留 3 天、14 个进程） | WebUI 终止只结束自身进程，不清理其派生的 sau.exe → node → chromium 子树；子树被过继为孤儿继续运行 |
| 2 | 同账号再次发布 | 新旧两个发布会话同时操作同一账号，平台风控概率抬高 | 孤儿任务不可见：任务列表随进程重启清空，用户无从得知后台还有发布在跑 |
| 3 | 用户自行清理 | 需打开任务管理器按进程树逐个结束，易误杀无关进程 | 缺少桌面端的身份识别 + 一键清理入口 |

**判定难点（探测器设计的关键约束）**：几乎每条进程祖先链都终止于已退出的
userinit 等系统进程——若沿祖先链上溯判"孤儿"，会把用户在终端里手动跑的发布
全部误判成僵尸。因此判定只看**直接父进程**，并叠加命令行身份、宽限期、
活子进程注册表、杀前重核验多层防线（见 §2.1）。

## 2. 变更清单

### 2.1 探测器服务（新增：`app/services/publish_zombies.py`，242 行）

零新增 Python 依赖，进程快照用一次 PowerShell CIM 查询：

- **快照采集**：`_query_processes()` 执行
  `Get-CimInstance Win32_Process | Select-Object ProcessId,ParentProcessId,Name,CommandLine,CreationDate | ConvertTo-Json -Compress`；
  脚本内显式 `[Console]::OutputEncoding=UTF8` 防中文标题乱码（实测踩坑，见 §3）；
  `CREATE_NO_WINDOW` 不闪窗，30s 超时（`_SNAPSHOT_TIMEOUT_SECONDS`），失败返回
  空列表只记 debug 日志，不阻塞 UI。
- **快照缓存**：`_process_snapshot()` 带 20s TTL（`_SCAN_TTL_SECONDS = 20.0`，
  `threading.Lock` 保护），不拖慢任务面板 2s fragment 刷新；非 Windows 平台
  恒为空（优雅降级）；`invalidate_cache()` 供杀灭后立即失效。
- **判定纪律（宁可漏报不可误杀）**，`detect_zombies()` 逐层过滤：
  1. **命令行身份**：`_is_publish_process()` 只认映像名 `sau.exe` 且命令行匹配
     `_PUBLISH_COMMAND_RE`——`sau(.exe)? <douyin|tencent|xiaohongshu|bilibili|kuaishou|weibo|baijiahao> <upload-video|upload-note>`（忽略大小写，路径可带引号）；
     chrome/python 子进程、`sau check`、`sau login` 一律不认。
  2. **自家活任务双保险**：PID 在 `live_publish_pids()` 注册表内、或直接父进程
     就是本 WebUI 进程（`os.getpid()`）的一律排除。
  3. **只看直接父进程**：`_parent_is_dead()` 判"父 PID 不在快照"或
     "父 PID 被复用（现持有者创建时间晚于子进程）"；**绝不沿祖先链上溯**。
     父进程健在的外部任务（用户终端手动发布、另一个 WebUI 实例）一律不碰。
  4. **60s 宽限期**（`_MIN_ORPHAN_AGE_SECONDS = 60`）：父进程刚退出、子进程
     正在收尾的瞬态不算僵尸；创建时间未知（解析为 0）时不设宽限但仍要求
     其余条件全部成立。
- **字段解析**：`_arg_value()` 提取 `--account`（缺省 `default`）、`--title`
  （支持引号值与裸值到下一个 `--flag` 为止）、`--file`；平台/动作取自身份正则
  分组；`_parse_created_ts()` 兼容 CIM `/Date(毫秒)/`（`_WMI_DATE_RE`）与 ISO
  字符串两种时间格式；结果按存活时长降序。
- **杀灭**：`kill_zombie(pid)` 三层防线后整树清理——
  ① 活注册表内的 PID 拒绝执行；② 按 PID 重拉 CIM（`ProcessId={pid}` 过滤）
  **重新核验命令行身份**，PID 复用/身份不符拒绝执行（宁可漏杀不可误杀）；
  ③ `taskkill /F /T /PID` 整树终止（含 node/chromium/conhost 子进程），输出按
  `encoding="oem"` 解码（taskkill 按控制台 OEM 代码页输出，中文系统为 GBK）。
  目标进程已自行退出按成功处理（目标已达成）；杀后 `invalidate_cache()`；
  成败均 loguru 留痕，返回 `{"success", "detail"}`。

### 2.2 活子进程注册表（修改：`app/services/social_auto_upload.py`）

- 新增模块级 `_live_pids: set[int]` + `_live_pids_lock`（threading.Lock），
  暴露 `live_publish_pids()` 返回快照副本。
- `_run_command` 在 `Popen` 成功后登记 `proc.pid`，`try/finally` 保证正常结束
  与超时杀树路径都注销——探测器据此排除本 WebUI 正在等待的发布子进程
  （父链核验之外的双保险）。既有 25 例 sau 服务测试不受影响（实测全绿）。

### 2.3 WebUI 警示区（修改：`webui/Main.py`）

- 新增 `_render_zombie_publishes()`（L1641）：任务管理面板顶部
  `st.expander("⚠️ 发现僵尸发布进程 (N)", expanded=True)` 警示区；
  每行展示标题（缺省回退文件名/PID）/平台/PID/账号 + 存活时长 +
  单个"终止"按钮（key `kill_zombie_{pid}`）；底部"全部终止"主按钮
  （key `kill_all_zombies`，逐个杀灭并汇总失败原因）。杀灭成功
  toast + `st.rerun()`，失败 toast 显示 detail；`detect_zombies()` 抛异常时
  静默返回，**不影响任务面板本身**。
- 新增 `_format_zombie_age()`（L1629）：存活时长格式 ≥1 天 `XdYh`、
  ≥1 小时 `XhYm`、其余 `XmYYs`，未知显示 `-`。
- 接线：`_render_task_manager_panel()` 开头调用（L1852），**先于空列表早退**
  ——重启后任务列表为空但孤儿进程仍在，恰是僵尸最常见的场景。
- 面板只含无状态按钮，headless AppTest 元素存在契约与 active-page fragment
  gating 不变（7 例 WebUI 契约测试实测全绿）。

  fragment 2s）自然补上；属防瞬态误判的预期行为。

  本文档与 [auto-publish-lessons.md](../auto-publish-lessons.md)。
- 同账号单发布、低频发布等既有风控约束不变（见
  [auto-publish-lessons.md](../auto-publish-lessons.md)）；探测器是兜底清理
  手段，不改变"尽量让发布在本会话内正常收尾"的主路径。
