本轮为 React 新版 UI 迁移期间的功能迭代，一天内完成三件事，驱动来源各异：
**API 任务队列路径的实时日志缺陷修复 + 右侧日志列改造为悬浮 LogDock**（缺陷根因

## 1. 背景与根因

| # | 场景 | 现象 | 根因 |
|---|------|------|------|
| 1 | API 队列路径提交的生成任务，在新版 UI 右侧实时日志面板观察 | 面板无任何进度输出；`/tasks/{id}/events` 与 `/tasks/{id}/logs` 对该任务无日志可推 | `app/controllers/v1/video.py` 的创建任务入口直接把 `tm.start` 提交给 TaskManager，工作线程内**没有安装任何 loguru sink**，`task_logs` 进程级缓冲始终为空。Streamlit 路径（`_run_generation`）有线程级 sink 安装逻辑，API 路径漏了同一包装——典型"迁移遗漏" |
| 2 | 无鉴权 Mode A 部署（`config.app` 既无 `api_key` 也无 `media_signing_key`） | `POST /api/v1/media/sign` 500，所有签名媒体（含任务详情视频回放、下载链接）全部失效 | 旧 `get_media_secret()` 仅有两级：配置项 `media_signing_key` → 主密钥派生；两者皆缺时抛 `MediaSignError`。而 `<video src>` 与跨域 `<a download>` 无法携带 Bearer 头，签名 URL 是媒体消费的必经链路——等于无鉴权部署下整个媒体面瘫痪 |
| 3 | 用户想浏览历史素材与成片 | 新版 UI 没有任何素材/成片查看入口和页面 | 迁移期间未覆盖（Streamlit 时代靠 `Main.py` 任务历史页的磁盘扫描兜底）；且任务状态在 memory 模式下重启即失，仅靠状态内任务清单无法覆盖历史目录 |
| 4 | 重启新版 UI（后端 8080 / dev 模式 Vite 5173） | 需手动找 pid、杀进程、起服务、开浏览器；盲目 taskkill 有误杀外部应用与端口未释放（WinError 10048）风险 | 无一键脚本；端口占用者身份未验证就杀是危险的默认行为 |

### 2.1 API 任务实时日志修复与 LogDock（对应提交批次 A）

- `app/services/webui_task.py`：
  - 新增 `run_api_task(task_id, params, stop_at="video")`（L124-136）——API 任务
    队列的线程入口包装：`add_task_log_sink(task_id)` 安装捕获 → `tm.start(...)` →
    `finally: remove_task_log_sink(...)`。docstring 记录根因（"工作线程内没有安装
    任何 sink，task_logs 缓冲始终为空"）。包装只负责日志捕获与清理，不改变流水线
    语义；`tm.start` 内部仍把流水线异常转换成失败终态。
  - `add_task_log_sink`（L93-111）：loguru sink 是进程级资源，按当前工作线程
    过滤（`log_scope_thread_id(record["thread"].id) == worker_thread_id` 且过
    `runtime_log_filter`），与 Streamlit 路径 `_run_generation` 共用同一安装逻辑
    与同一份 `task_logs` 缓冲；辅助线程经 `bind_log_scope` 归属工作线程，日志同样
    收集。
  - `remove_task_log_sink`（L114-121）：`logger.remove` 的 `ValueError`（sink 已
    失效）静默忽略，保证 finally 清理幂等。

### 2.3 一键重启启动脚本（对应提交批次 C，2026-11-24 补充完成）

- `start-web.bat`（仓库根目录，新增，199 行）：双击/命令行一键重启新版 UI。
  `start-web.bat` = 重启后端并打开 `http://127.0.0.1:8080`（内嵌新版 UI，单源
  Mode A）；`start-web.bat dev` = 额外重启 Vite 热更新服务器并打开
  `http://localhost:5173`。
- **身份验证后才杀端口**：`:kill_port`（L141-180）用 `netstat -ano -p tcp` 找
  目标端口 LISTENING pid，再经 PowerShell `Get-CimInstance Win32_Process` 校验
  命令行正则——后端 8080 仅匹配 `main\.py web`（L36），dev 模式 5173 仅匹配
  `vite`（L52）；外部应用占用时 `KP_FOREIGN=1` → `:fail_foreign_backend`
  明确报错且**不误杀**（L120-126，提示可改脚本内 `BACKEND_PORT` 换端口）；
  `KP_SEEN` 对同 pid 去重。
- **杀后等待端口释放**：`:wait_free`（L185-198）阻塞轮询直到端口离开
  LISTENING（≤10 次 ping 间隔，超时仅告警），避免旧进程尚未退净时新实例
  `WinError 10048` 绑定失败。
- **Python 只认项目内解释器**：`.venv\Scripts\python.exe` →
  `lib\python\python.exe` 兜底（L42-43），两者皆缺 `:fail_no_python` 退出
  （L128-134）；绝不使用机器全局 Python。
- **curl 就绪轮询**：后端 `http://127.0.0.1:8080/` 60 次 ×1s（L64-73），
  dev 模式 Vite `http://localhost:5173/` 45 次 ×1s（L85-94）；返回 200 才自动
  开浏览器（embedded 开 8080；dev 开 5173；Vite 超时则回落打开内嵌 UI，
  L101-105）。
- **编码与延时契约**：全文纯 ASCII + CRLF（防控制台代码页乱码，L18 注释）；
  延时用 `ping -n 2 127.0.0.1` 而非 `timeout /t`（stdin 被重定向时后者挂起，
  L19 注释）。
- 实测：杀旧实例 pid 47836 → 新实例 pid 31256，根路径 200、
  `/api/v1/task-dirs` 200。
