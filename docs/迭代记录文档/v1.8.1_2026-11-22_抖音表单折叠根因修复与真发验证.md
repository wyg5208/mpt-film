## 1. 故障与根因

| # | 场景 | 现象 | 根因 |
|---|------|------|------|
| 1 | headed 真发 run5/run6 | 自愈恢复表单成功（截图可见完整表单）后 ~1s 标题输入框消失，填写循环空等 | 填写循环每轮调用 `_dismiss_guide_overlays`，盲删包裹整个表单的 `publish-mention-wrapper-*` → React 重渲染折叠成"快速填写"态 |
| 2 | headless 时序探针（`temp/probe_draft_timeline.py`） | 表单全程稳定，复现不了折叠 | 该探针不调用 dismiss，不触发删除 |
| 3 | 用户手动"暂存离开→重进"救援 | 表单立即渲染且不再折叠 | 手动路径不删 DOM |

三个现象同一根因。headed 每秒采样探针 `temp/probe_headed_collapse.py`（t≈2s 处
调用 `_dismiss_guide_overlays`，与填写循环一致）实测：**dismiss 调用后 1s 内输入框
必消失**；采样 JSON（`temp/probe_headed_collapse.json`）记录
`mw_classes=["publish-mention-wrapper-LWv5ed"]`、`mw_wraps_form=true`、
`mw_in_portal=[false]`——新版 UI 该类名包裹整个基础信息表单且不在 semi-portal 内。

**教训**："抗干扰/清浮层"的删除清单必须随平台改版重新验证；类名复用
（dropdown wrapper → 表单容器）会把抗干扰变成自毁；headed/headless 行为差异要用
同条件探针定罪，不靠猜。
