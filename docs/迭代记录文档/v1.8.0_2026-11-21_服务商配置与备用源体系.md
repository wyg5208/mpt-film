# 2026-11-21 迭代记录（v1.8.0）：服务商配置与备用源体系

本轮迭代把散落在创作面板各处的服务商 Key 表单集中收敛为统一的**服务商配置页**，
并在此基础上建立**三槽备用源体系**：素材来源、配音、LLM 文本生成三条链均支持
"第一优先 + 备用 1 + 备用 2"，主源未配置凭证时任务预检/调用点自动切换到备用槽，
不再直接失败。驱动来源是用户对配置入口混乱的反馈与"服务商一处配置、全局生效"
的产品诉求（实施方案见相关文档）。

版本号按"每次迭代必升版"政策由 `1.7.0` 升至 **`1.8.0`**（minor：新增功能）。
本文档全部代码符号、配置键与测试断言均于当日 Grep/代码核实；本文档期另做了
升版后最小验证（§3.6，实测）。事实清单中两处与代码不符的点已按实际实现修正：
`VideoSourceResolution` 字段为 `source/primary/switched/attempts`（非 resolved/
switched_from）；`codex_oauth.py` 的 User-Agent 是**硬编码** `ChangoFilm/1.7.0`
×2（并非动态取 `__version__`），升版时已同步改写（§2.5）。

## 1. 任务目标与设计决策（锁定）

| # | 决策 | 内容 | 关键约束 |
|---|------|------|---------|
| 1 | 不删除任何服务商 | 聚合平台全部移到注册表尾部，保留 affiliate 链接契约与老用户配置兼容 | `DEFAULT_LLM_PROVIDER_ID` 不变（moonshot） |
| 2 | 一处主源原则 | `config.app.video_source` 仍是唯一主源键；素材页 TAB 的"第一优先"槽与创作页下拉写同一键（双向同步）；备用槽按能力分组新键存储 | 创作页下拉与素材页选择互相同步，不产生第二份主源 |
| 3 | 能力即素材分组 | AI 视频 / AI 图片 / 库存视频 / 库存图片四组；备用链仅在主源所属能力内生效，跨能力不互备 | `local` 不参与备用链（依赖本次上传文件） |
| 4 | TTS 链入口 | 配音三槽链放在服务商配置"配音" TAB（`tts_server` + 2 个备用键）；音频面板保留配音模式/音色/语速音量参数，移除服务下拉与 Key 输入 | 音频面板零 Key 控件、零 `tts_server` 控件 |
| 5 | 能力矩阵不虚标 | 服务商配置页总览矩阵只声明真实已接线的能力（图片识别、图片编辑、视频编辑未接线不声明） | "是什么"由目录维护，"怎么调用"仍在服务层适配器 |

  - `SERVICE_PLATFORMS` 平台目录共 **56 家**（国内厂商 11 / 本地与免费引擎 6 /

    + RuntimeError）；服务 id 按 `(kind, id)` 四命名空间索引（聚合平台的 LLM id
    与素材 id 可同名，如 infistar），重复即抛错；`("material", "local")` 显式
    映射到 comfyui 平台（本地文件不属于在线平台）。
  - 能力常量 8 个（`CAP_TEXT` / `CAP_IMAGE_GEN` / `CAP_T2V` / `CAP_I2V` /

  - `MATERIAL_CAPABILITY_GROUPS`：ai_video（8 家）/ ai_image（2 家）/
    stock_video（3 家）/ stock_image（2 家），与 WebUI `VIDEO_SOURCE_GROUPS`

    映射到能力分组。
  - `platform_for_service` / `capabilities_for_service` 按命名空间返回真实
    接线能力（LLM → text；tts → tts；music → music；素材过滤为图片/视频能力）。
- `app/models/llm_provider.py`：`LLM_PROVIDER_REGISTRY` 重排为 **45 家**
  新顺序——国内厂商（moonshot, kimi_code, deepseek, qwen, volcengine, minimax,
  mimo, iflytek, modelscope）→ 本地/订阅（ollama, llamacpp, claude_code,
  openai_codex, openai_chatgpt）→ 国际主流（openai, anthropic, gemini, azure,
  grok, groq, cloudflare, litellm, oneapi, pollinations）→ 聚合平台尾部
  （muse_spark 起 21 家：muse_spark, jalapeno, infistar, shengsuanyun, apimart,
  aihubmix, aimlapi, evolink, openrouter, api_route, fluxionai, cheaperinference,
  requesty, futureinfra, yapi, opper, onomeo, empiriolabs, runcrate, cloudgpu,
  cheapaimodel）。`DEFAULT_LLM_PROVIDER_ID = "moonshot"` 不变；registry 自检
  重复 id 逻辑保留。所有 affiliate 端点 URL 原样保留。
- `app/services/llm.py`：新增 `provider_override` contextmanager（模块级
  `_PROVIDER_OVERRIDE_STACK` + `_active_provider_override()`）；`_generate_response`
  解析 Provider 时优先读覆盖值（`_active_provider_override() or config`），覆盖
  与 `config.toml` 主 Provider 解耦，只影响当次调用。
- 新建 `app/services/source_failover.py`（331 行）：任务预检的备用源解析。
  - `video_source_available(source_id, settings, *, codex_connected=False)`：
    单个素材来源就绪检查，**只验证本地配置齐全、不做连通性探测**（口径同
    `webui/settings_providers.py` 的"已配置"检查）；库存类经 `STOCK_KEY_CONFIG`
    查 Key（库存图片与库存视频共用同批 Key）；各聚合平台走各自 `is_enabled`；
    `codex_image` 按 `codex_connected` 判定；未知来源按可用处理，交由任务自身
    逐源预检给出明确错误。
  - `VideoSourceResolution(source, primary, switched, attempts)` +
    `resolve_video_source(app_config, *, preferred, codex_connected)`：候选链
    `[主源, 备用1, 备用2]`，备用槽按主源所属能力读取
    `video_source_backups_{capability}_{slot}`（capability ∈ ai_video/ai_image/
    stock_video/stock_image），`NON_FALLBACK_SOURCES = {"local"}` 排除本地素材；
    切换成功写 warning 日志（`video source ... unavailable; switched to backup
    source ...`），全链不可用写 error 日志并返回空 `source`。
  - `tts_server_available` + `TTS_SERVER_REQUIREMENTS`（**11 家**配音服务的
    本地凭证要求，None = 免费/自托管默认可用；minimax-tts 支持"独立 Key 或
    复用 LLM Key"多候选）+ `_AUTO_VOICE_SERVERS`（音色列表来自本地静态目录的
    9 家）：`resolve_tts_server` 按 `[主配音, 备用1, 备用2]` 解析
    `tts_server` / `tts_server_backup1/2`；MiniMax/ElevenLabs 音色需在线拉取，
    **不参与自动切换**；切换时 `_pick_fallback_voice` 按语言前缀挑默认音色，
    挑不到音色等同不可用继续尝试下一家；返回
    `TtsServerResolution(server, voice_name, primary_server, switched, attempts)`。
  - `resolve_llm_chain(app_config)` → `LlmChainResolution(chain, primary)`：按
    `llm_provider` + `llm_provider_backup1/2` 顺序去重返回重试链（就绪与否由
    调用点以异常驱动，不做预检）。
- `app/services/task.py` 预检与调用点接线：
  - `_run_pipeline` 在**全部 per-source 预检之前**先跑链解析（注释明示"解析
    必须先于逐源预检：后续 jalapeno/codex 等块看到的已是切换后来源"）：
    `resolve_video_source(config.snapshot_config_with_pending(config.app),
    preferred=params.video_source, codex_connected=codex_ready)`（codex 就绪度
    经 `codex_oauth.account_status()`，异常按 False）；链上无可用来源 →
    `_mark_task_failed(task_id, "preflight", "no usable video source; configured
    source chain unavailable: " + 失败明细)`；`switched=True` 时
    `params.video_source = video_resolution.source`——**只改本次任务参数，
    不写回 config.toml**。
  - TTS 预检链切换：`resolve_tts_server(config.snapshot_config_with_pending(
    config.ui), language=params.video_language)`，全链不可用 → "no usable tts
    server; configured voiceover chain unavailable: ..."。
  - 新增 `_generate_text_with_failover(description, call, *args, **kwargs)`：
    覆盖 `generate_script` / `generate_terms` / `generate_script_plan` 三个
    LLM 调用点；链长 ≤1 直接调用；否则逐个 provider 包 `llm.provider_override`
    重试，切备写 warning（`... retrying with backup provider ...`），全链失败
    抛最后一次异常保留原有失败语义；`KeyboardInterrupt`/`SystemExit` 直接上抛。

## 5. 遗留与边界

1. **全部变更未提交**：本轮 Phase 1–4 + 升版产物均在工作区；按 §2/§4 批次划分
   交由 `version-release` 流程入库，升版产物与本文档纳入 `release: v1.8.0`
   批次；本 agent 不做 Git 提交。
2. **`config.example.toml` 未补备用槽示例键**：`video_source_backups_*/`、
   `llm_provider_backup1/2`、`tts_server_backup1/2` 三组键仅由 UI 写入本地
   配置，示例文件与新用户文档暂无键位说明；建议后续批次补示例与说明。
3. **uv.lock 漂移风险**：本机 uv 配置指向清华镜像，`uv lock` 会整体改写
   registry URL 与 revision（已用备份还原、改手工单行编辑）；后续升版若需
   `uv lock`，先归一 registry 源，或沿用手工编辑自条目的做法。
4. **就绪口径边界**：备用链就绪检查只看本地配置齐全、不做连通性探测；未知
   素材来源按可用处理、交由 per-source 预检给出明确错误（`video_source_available`
   末段）；`codex_image` 的就绪依赖预检时点 `codex_oauth.account_status()`。
5. **TTS 自动切换范围**：MiniMax/ElevenLabs 音色列表需在线拉取，不参与自动
   切换（`_AUTO_VOICE_SERVERS` 排除）；自动切换时按语言前缀挑默认音色，挑不到
   即放弃该槽。
6. **LLM 失败转移语义**：只对文本生成三个调用点生效（脚本/关键词/分镜方案），
   切换不写回 WebUI 选中值；就绪与否由异常驱动，不做预检。
7. **基线既有失败**：全套件残留 22 个失败全部为基线环境类问题（launcher、
   TLS 探测、ffmpeg env 等），后续迭代如需收敛另立批次。
8. **测试文件计数口径**：事实清单记 24 个更新测试文件，git 实测 28 个
   （+573/−299）；本文档以 git 实测为准，差额 4 个属计数口径差异。
