# 2026-11-09 迭代记录：TTS 声音语言匹配与渲染稳定性

本次迭代由三个真实故障驱动，全部来自当天的实际生成任务。核心结论：管线本身工作正常，问题集中在
**"声音与脚本语言不匹配"这一配置错误的两种表现形态**，以及 **渲染编码路径未利用硬件**。

---

## 1. 故障与根因

| # | 任务 | 现象 | 根因 |
|---|---|---|---|
| 1 | `d1bc00b8`（10:35） | azure_tts_v1 用 `af-ZA-AdriNeural` 读中文脚本，`NoAudioReceived` 连续失败 3 次，任务失败于 audio 阶段，错误信息只说"检查连接" | edge-tts 7.3.1 在服务端正常握手但返回零字节音频时抛 `NoAudioReceived`——这是**确定性**的配置错误（声音语言 ≠ 脚本语言），不是网络抖动，3 次重试全部浪费 |
| 2 | `5768b4d0`（11:12） | 同样的 af 声音 + 中文脚本，这次任务"成功"，但成片只有 1.97 秒 | 脚本里夹了英文单词 "Agent"（出现两次），af 声音只会念这两个词，产出 1.94 秒音频（`audio.mp3` 仅 11.6 KB）；视频时长跟随音频，于是"静默成功"产出一个近空视频——比故障 1 更隐蔽 |
| 3 | `d6bf5740`（11:17） | 58.6 秒的成片，渲染合计超过 17 分钟仍未结束 | 三处编码全部跑 libx264 纯 CPU 软编，且线程被 `n_threads=2` 限死、30 段素材串行处理——而机器是 i9-14900HX（24C/32T）+ RTX 5090 Laptop，GPU 全程闲置 |

三个故障的共同点：**失败要么被误判为别的原因，要么根本没被当成失败**。

## 2. 变更清单

### 2.1 NoAudioReceived 快速失败（未提交批次 1）

- `app/services/voice.py`：`azure_tts_v1` 重试循环单独捕获 `NoAudioReceived`——只尝试 1 次，日志点名声音并给出语言不匹配提示，然后 `break`；瞬时异常仍保留原有 3 次重试。
- `app/services/task.py`：`generate_audio` 失败信息带上声音名，并点出最常见诱因（声音与脚本语言不匹配）。
- 测试：`test/services/test_azure_tts_no_audio.py`（2 例：NoAudioReceived 恰好 1 次尝试、瞬时错误仍 3 次重试）。

### 2.2 webui.bat 单实例重启（未提交批次 2）

- 新增 `webui_port.ps1`：解析主机地址 → 探测首选端口（`ExclusiveAddressUse` 绑定测试）→ 端口被占时按命令行特征（同时含 `streamlit` 与 `main.py`）识别是否为本 WebUI 的残留实例：是则强制结束并轮询端口释放（最多 3 秒），**外部应用绝不误杀**，改用 8502–8599 依次回退。
- `webui.bat`：端口探测改为调用该脚本（`for /f` 捕获 stdout 的端口号）。
- 细节：提示语走 `[Console]::Error.WriteLine`——批处理 `for /f` 只捕获 stdout，`Write-Host` 的信息流会被丢弃。
- 已验证：真实双击演练（旧实例被杀、新实例独占 8501）、外部占用者保护演练、提示语可见性。

### 2.3 zh 系声音置顶（未提交批次 3，含 2.4）

- `app/services/voice.py`：`get_all_azure_voices` 由纯字母序改为分组序——`zh-` 前缀（15 个）置顶，组内与其余语言仍按字母序；总量 331 不变，`af-ZA-AdriNeural-Female` 从第 1 位落到第 16 位。
- 动机：字母序让 af（南非荷兰语）天然排最前，是多次选错声音的直接诱因。
- `test/services/test_voice.py`：排序契约同步更新（zh 组置顶、两组各自字母序）。

### 2.4 音频时长健全性守卫（未提交批次 3）

- `app/services/task.py` `generate_audio`：TTS 分支在零时长检查之后新增守卫——
  - 触发条件：脚本 CJK 字符数（`[\u4e00-\u9fff]`）> 50 **且** 取整前的实测音频时长 < 5.0 秒；
  - 行为：任务在 audio 阶段失败，信息包含实测时长、CJK 字符数、声音名与语言不匹配提示；
  - 细节：比较用取整前的实测秒数（避免 `ceil` 把 4.1s 抬到 5 漏判）；自定义音频是用户自备素材，不在守卫范围；守卫位于任务层，覆盖全部 TTS provider。
- 测试：`test/services/test_audio_sanity_guard.py`（4 例：拦截/放行/短文案不误伤/5.0 秒边界）。

### 2.5 渲染加速配置（本地 config.toml，不入库）

```toml
video_codec = "h264_nvenc"      # 三处编码交给 RTX GPU，运行时失败自动回退 libx264
video_clip_concurrency = 5      # 30 段素材并行预处理（原 1 串行）
```

- 生效前提：重启 `webui.bat`（运行中的进程持有旧配置）。
- 已验证：配置解析通过、`_get_effective_video_codec()` 返回 `h264_nvenc`、bundled ffmpeg 对 RTX 5090 实测编码成功。
- 事故插曲：手工插入 `video_clip_concurrency` 时与 `[app]` 中应用自管的同名键重复，导致配置解析失败；已改为原位改值。教训：**`[app]` 是应用运行时会回写的表，插键前必须全文搜索**。

## 4. 遗留与边界

1. **三批未提交**：TTS 修复（voice.py / task.py / 新测试）、启动器（webui.bat / webui_port.ps1）、zh 置顶 + 守卫（voice.py / task.py / test_voice.py / 新测试）。待实测确认后分主题提交。
2. **渲染天花板**：成片字幕合成走 MoviePy 的 Python 逐帧管线（单线程），GPU 编码无法完全覆盖——1 分钟成片优化后预计仍需 3–5 分钟。
3. **NVENC 码率策略**：NVENC 默认恒定码率与 libx264 的 CRF 不同，首个实测成片如画质下降，需在编码路径补充显式 bitrate/QP 参数。
4. **n_threads 无 UI 入口**：默认 2（schema 上限 16），API 调用方可显式传入；WebUI 若要暴露需另加表单项。
5. **素材集漂移**：seed 确定性只覆盖编辑决策，Pexels 素材库变化仍会改变可用素材（既有边界，本次未涉及）。
