# 2026-11-14 迭代记录：Web 创作对话与自适应 PWA（ChangoVideo Studio）

把桌面版的"大模型对话创作"接入**已有的** Web Studio（`opensources/changovideo/packages/changovideo/studio`），
做成自适应 PWA：宽屏右栏对话、窄屏全屏覆盖，经上一篇迭代的 Cloudflare Tunnel 公网即可创作。
**没有新建独立应用**——工作集中在四块：共享 Pi 内核与 Web 后端、BYOK 模型设置页、桌面前端移植与 PWA 外壳、
公网工具收紧；收尾验证驱动出两处 UI 修复、一处 public-check 脚本修复、一处 agent-hub 修复与一处 PWA 离线壳修复，
并把新代码部署到生产 Studio（固定域名公网）复验。

用户已确认的决策：Studio 内集成（不新建独立应用）；引擎用内置 Pi agent + 用户自带密钥 BYOK
（不远程驱动本机 CLI）；本期不预置任何 key。

## 1. 任务目标与架构接缝（代码中逐一核实）

桌面创作对话（`apps/desktop/chat`）依赖 Electron 桥与本机 ACP 进程，Web 端要补上四件事：

| # | 缺口 | 核实结论与落点 |
|---|---|---|
| 1 | Pi 内核锁在桌面目录 | `pi-agent.mjs / pi-config.mjs / chat-store.mjs` 纯 Node、零 Electron 依赖——搬入 changovideo 包共享，桌面改从新位置导入 |
| 2 | Web 无 agent 后端 | 每项目一个 Pi 子进程（ACP over stdio），turn 投影到项目既有 WebSocket，密钥门/写 Origin 检查复用 |
| 3 | 模型与密钥无 Web 入口 | BYOK：用户自带 key，只写不回显、绝不进日志/argv，系统级封存 |
| 4 | 公网工具面失控 | Pi 自身无沙箱（restricted-tools.mjs 引其 docs/security.md）：工作目录不约束工具，公网必须逐调用收紧 |

**关键约束**：渲染仍在本机宿主（Playwright + ffmpeg），公网只是创作入口；本地/桌面不配 `restricted` 时
工具行为**逐字节不变**（全量工具只属于本地，公网 fail-closed）。

### 2.7 P5 agent-hub 修复 `fix(studio): retire a project's Pi agent when the person's models change`（85afbe7）

全链路 E2E（§3.8，本地 stub 模型）发现：Pi 在进程出生时拿模型清单（`CHANGOVIDEO_PI`），而 hub 每项目复用同一
进程——用户在设置页改/删/增模型后，下一 turn 仍用出生时的旧地址/旧 key，表现为 Connection error。修复：
`ensureAgent` 比对 harness 签名（models+env 的 JSON），变化即结束旧进程、以当前配置新起；会话落盘
（`.film/chat/agent/`），新进程经 `session/resume` 接续原对话。exit handler 仅在 map 仍指向该 agent 时移除条目，
防旧进程迟到的 exit 误删新进程。回归测试：配置不变复用进程、变化后新进程拿新配置、对话跨重启延续（hub 15/15）。

### 2.8 P5 PWA 离线壳修复 `fix(studio): keep the PWA offline shell keyless and unredirected`（7675536）

生产浏览器验证（§3.9）发现：深链登录后**离线打开失败（ERR_FAILED）且缓存里留着 key**。根因不在导航分支而在
**install 预缓存**：`cache.addAll(['/'])` 带着会话 cookie 请求裸 `/`，而服务器对已登录的裸 `/` 应答
**302 → `/?key=…`**（server.mjs 的“key 留在地址栏”行为）——addAll 跟随重定向并把**最终应答**存为壳：
`redirected:true`、URL 带 key、URL 列表不含 `/`，浏览器拒绝它作离线导航应答。修复（`studio/ui/public/sw.js`）：

- install 改用 `fetch('/', { credentials: 'omit' })` 预缓存页面——不带会话时同一壳直接 200、无 key；
  仅保留直接且 ok 的应答；
- 导航刷新壳的条件收紧为“直接 + 无 key 的 `/` 应答”（已登录地址都带 `?key=…`，重定向应答一律不存）；
- 壳缓存名 v1 → **v2**：activate 既有“删除其它缓存”逻辑随之清掉已中毒的 v1，老浏览器升级即自愈。

新增 `sw.test.mjs`（VM 模拟 worker 全局，Chrome 的 Cache.put 确实存重定向应答，mock 从实）：已登录 install、
深链/带 key 导航、离线应答、v1 清除、普通访问刷新、API/影片/外源/写不拦截、壳资产 cache-first，共 8 例。
包 test 脚本 glob 增 `studio/ui/public/*.test.mjs`。配套构建清理（bae35ff）：vite 将 public/ 整体拷入 dist/，
sw.test.mjs 随之发布给浏览器并被递归测试重复计数——构建插件在拷贝后从 dist/ 剔除 `*.test.mjs`，壳文件不变。

### 2.9 P5 钥匙门引导 `fix(studio): explain the key gate when the projects list is refused (401)`（99392ea）

用户报“本地 4747 与公网都显示无法加载你的项目、控制台全 401”。取证确认**非缺陷**：服务器健康、深链
`/open?key=…`→302 设 cookie→`/api/projects` 200（localhost 与 127.0.0.1 两 host 均验）；前端 `api.ts` 用同源
相对路径，日志里的 `localhost:4747` 说明页面即从该 host 打开而未带 cookie。401 是第二道门（key 门）在起作用：
cookie 绑定 host（localhost≠127.0.0.1）、会话级（关浏览器即失效）、公网需先过 Access 再走深链；裸网址永不登录。
但原 UI 仅显示“无法加载/重试”，读起来像故障。修复：`lib/projects-page.ts` 增纯函数 `wantsKey`（按 error.status
读 401，保持该模块无运行时导入），`ProjectsLibrary.tsx` 增 `needsKey` 状态，在 loadFailed 分支追加五语言引导
（`projects.loadFailedKey`）：用启动时打印的完整深链打开、登录只属打开链接的那个 host、关浏览器失效、公网先
Access 再深链。新增 4 单测（该文件 7/7）。
