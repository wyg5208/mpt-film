**没有新建独立应用**——工作集中在四块：共享 Pi 内核与 Web 后端、BYOK 模型设置页、桌面前端移植与 PWA 外壳、

用户已确认的决策：Studio 内集成（不新建独立应用）；引擎用内置 Pi agent + 用户自带密钥 BYOK

## 1. 任务目标与架构接缝（代码中逐一核实）

桌面创作对话（`apps/desktop/chat`）依赖 Electron 桥与本机 ACP 进程，Web 端要补上四件事：

| # | 缺口 | 核实结论与落点 |
|---|---|---|
| 1 | Pi 内核锁在桌面目录 | `pi-agent.mjs / pi-config.mjs / chat-store.mjs` 纯 Node、零 Electron 依赖——搬入 changovideo 包共享，桌面改从新位置导入 |
| 2 | Web 无 agent 后端 | 每项目一个 Pi 子进程（ACP over stdio），turn 投影到项目既有 WebSocket，密钥门/写 Origin 检查复用 |
| 3 | 模型与密钥无 Web 入口 | BYOK：用户自带 key，只写不回显、绝不进日志/argv，系统级封存 |
| 4 | 公网工具面失控 | Pi 自身无沙箱（restricted-tools.mjs 引其 docs/security.md）：工作目录不约束工具，公网必须逐调用收紧 |

**关键约束**：渲染仍在本机宿主（Playwright + ffmpeg），公网只是创作入口；本地/桌面不配 `restricted` 时
工具行为**逐字节不变**（全量工具只属于本地，公网 fail-closed）。

### 2.8 P5 PWA 离线壳修复 `fix(studio): keep the PWA offline shell keyless and unredirected`（7675536）

生产浏览器验证（§3.9）发现：深链登录后**离线打开失败（ERR_FAILED）且缓存里留着 key**。根因不在导航分支而在
**install 预缓存**：`cache.addAll(['/'])` 带着会话 cookie 请求裸 `/`，而服务器对已登录的裸 `/` 应答
**302 → `/?key=…`**（server.mjs 的“key 留在地址栏”行为）——addAll 跟随重定向并把**最终应答**存为壳：
`redirected:true`、URL 带 key、URL 列表不含 `/`，浏览器拒绝它作离线导航应答。修复（`studio/ui/public/sw.js`）：

- install 改用 `fetch('/', { credentials: 'omit' })` 预缓存页面——不带会话时同一壳直接 200、无 key；
  仅保留直接且 ok 的应答；
- 导航刷新壳的条件收紧为“直接 + 无 key 的 `/` 应答”（已登录地址都带 `?key=…`，重定向应答一律不存）；
- 壳缓存名 v1 → **v2**：activate 既有“删除其它缓存”逻辑随之清掉已中毒的 v1，老浏览器升级即自愈。

新增 `sw.test.mjs`（VM 模拟 worker 全局，Chrome 的 Cache.put 确实存重定向应答，mock 从实）：已登录 install、
深链/带 key 导航、离线应答、v1 清除、普通访问刷新、API/影片/外源/写不拦截、壳资产 cache-first，共 8 例。
包 test 脚本 glob 增 `studio/ui/public/*.test.mjs`。配套构建清理（bae35ff）：vite 将 public/ 整体拷入 dist/，
sw.test.mjs 随之发布给浏览器并被递归测试重复计数——构建插件在拷贝后从 dist/ 剔除 `*.test.mjs`，壳文件不变。

### 2.12 P5 web agent CLI 可达性修复 `fix(studio): make the changovideo CLI reachable from the web agent`（b139d50）

活体闭环（§3.15）建片成功，但配音 turn 暴露 **bash 工具全部 127**（`changovideo: command not found`，ffmpeg 同样）。
根因三层：① 桌面端启动时往 `<home>/agent/bin` 写 sh/cmd shim，web hub 从未写；② Windows 上 Pi 只在 C 盘找 bash，
找不到即回退 System32 bash（WSL Linux），命令不在本机跑；③ hub 用 `sep`（`\`）而非 `delimiter`（`;`）拼接 PATH
列表——首条目与原 PATH 在 JS 层就粘成 `bin\C:\Python314\Scripts\`，任何 shell 转换都救不回。修复：
`cliCommand(home)` 在 hub 启动时写运行时 shim（sh+cmd，chmod 755）；`windowsBash()` 经 PATH 上的 git.exe 发现
Git Bash（本机 `D:\Program Files\Git\bin\bash.exe`），以 `shellPath` 传入 Pi（`SettingsManager.inMemory`）；
PATH 在环境既有 path key（Windows `Path` 大小写，避免重复键）下以 `delimiter` 前置 bin 目录。实证普通 Windows
PATH 由 Git Bash/MSYS 原生转换，**无需** msysPath/MSYS2_ENV_CONV_EXCL/自定义 bash 工具（早期“MSYS 粘 PATH”
诊断被对照实验推翻：正确 `;` 拼接 status 0 输出 0.2.7，错误 `\` 拼接 127）。回归测试新增 4 例：shim 内容、
bash 发现、spawn env/config 断言、活体 Git Bash shim 运行；agent-hub **19/19**、agent 区 **57/57**。

### 2.13 P5 Edge TTS 挂起修复 `fix(studio): stop Edge TTS when the run is stopped, so a blocked endpoint cannot hang the turn`（3c58aa1）

CLI 修好后生产配音 turn **挂起 20+ 分钟**：edge-tts-universal@1.4.0 的 `_stream()` 在连接失败时无限 await
websocket 的 `open` 事件（error/close 被推进无人读取的 messageQueue），库本身不收 abort 信号；服务器 get 的
deadline（tts 300+60=360s）虽 abort 了 ctx.signal，旧 edge.mjs 却只在 for-await 循环体内查 signal，永远走不到。
修复：`abortable(stream, signal)` 生成器把每步 `it.next()` 与 `stopped(signal)`（abort 即 reject 的 promise）竞速，
voice 动词的 `VoicesManager.create()` 同样竞速——deadline abort 与用户取消都能即刻终止。回归测试：永不回答的
流被 run 的 abort 停掉（edge **5/5**，providers 区 **167/167**，tools 在 PATH）。
