# 2026-11-14 迭代记录：公网助手自省能力（ChangoVideo Studio）

公网创作对话里问「系统现在有那些服务商和服务」，助手答非所问（"changovideo get 找不到命令" + 泛泛的服务商大全）。
本篇把根因取证到底，并补上**真实的能力缺口**：新增 `changovideo status` 一条命令（服务端 `GET /api/status` 聚合路由 +
CLI 双通道），让助手在回答系统能力/已连服务/项目内容之前**先跑一条命令、据实回答、用已连接的服务直接开工**。
受限白名单、路径禁闭、Pi 工具面**一律不动**；密钥（连 last4）永不出服务端。旧进程栈退役、生产重启加载新路由，
本地生产 e2e 复现原提问全真，开工冒烟真实出图。

用户目标（原话归纳）：完善系统提示词和体系内部工具集，让助手可以快速找到相关信息并开工——服务商信息、项目信息、
素材信息、工具信息、预设风格信息和技能、公用素材等。

## 2. 设计决策

- **一条 changovideo 命令**：新 verb `status` 天然通过现有受限白名单（`restricted-tools.mjs` 不改、不新增 Pi 工具、
  不放宽禁闭）——公网工具面零扩张。
- **服务端聚合**：`GET /api/status?folder=&section=` 复用现有 seams（keys/providers/get/skills/examples/film/chat），
  走既有 launch-key 鉴权；**永不回传密钥**（连 last4 也不给 agent——编辑页看 last4，agent 不需要）。
- **每件事只说一遍**：手册（MANUAL.md，已内嵌进系统提示词）写全 status 用法与意图→动作映射；`agent-prompt.md`
  只加一句指引；`RESTRICTED_NOTE` 不动（只讲限制）。
- **连接 = 配置，不是存活**：status 只报告密钥/一键配置状态，不做服务商存活探测（避免延迟与抖动；
  运行期错误由 `get` 承担，机器诊断由 `doctor` 承担）。
- **有界输出**：项目文件树上限 400 条（超限 truncated）、examples 上限 30；跳过 `.film`/`node_modules`/`.git`，
  只深入 `assets/` 与 `skills/`；symlink 只列名不跟随。
